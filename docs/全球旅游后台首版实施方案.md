# finger-more 全球旅游后台首版实施方案

首版建设一套能协作维护、核验来源和按版本发布的中英文旅游资料后台。运营按地理树找到地点，按业务维度维护资料，通过选择器引用字典和主数据。每项事实有唯一维护入口，每个发布版本都能追溯到当时审核的资料。本文定义首版目标和验收规则，原型行为可查现有架构和源代码。 [项目架构与核心模块](项目架构与核心模块.md)

研发实施按开发规格中的数据模型、接口约定、样例输入、运行命令和验收证据执行。 [首版开发规格](全球旅游后台首版开发规格.md)

## 01 首版交付与全旅程覆盖目标

| 层次 | 达成标准 |
| --- | --- |
| 首版后台 | 维护多国家的稳定资料，支持账号语言授权、中英文协作、选择关联、审核、发布、取消发布和历史预览。 |
| 首批数据 | 用南京纪念馆跑通机构、多馆区、入口、常设展、历史资料和国家标准。用新加坡国家博物馆验证不同地理层级。跨国标准复用和地区例外通过测试数据验收。 |
| 全旅程覆盖 | 按「出发市场 × 目的地 × 旅客语言 × 场景」计算就绪程度。景点资料可以独立发布。关键步骤都达到验收标准后，相应旅程才标记为完整覆盖。 |

首版优先录入稳定资料。入境条件、价格、开放日历、预约名额和临时变更纳入整体数据设计，按来源、适用条件和生效时间逐步接入。一个目的地可以先发布完整的中英文景点资料，再逐步补齐行前、求助和返程信息。

开工样本固定为南京纪念馆和新加坡国家博物馆。每批以实体、来源、语言和引用清单为交付边界。样本通过后再分别估算其余资料的补译、核验和迁移工作量。 [首批样本与测试数据](全球旅游后台首版开发规格.md#02-首批样本与测试数据)

## 02 地理树与业务关联

地理路径示例为 **中国 → 江苏省 → 南京市 → 建邺区 → 纪念馆馆区 → 馆内点位**。行政区按各国实际结构维护，允许合法跳级。每个地点有稳定 ID 和一个主地理归属。专题、线路和跨地区旅游区域通过选择成员地点组织。

| 对象 | 负责维护的事实 |
| --- | --- |
| 运营机构 | 纪念馆正式名称、别名、官方渠道和机构简介。各馆区通过选择关联同一机构。 |
| 馆区 | 地址、邮编、坐标、一个直属行政区以及主要运营机构。馆区入口列表通过关联读取。 |
| 馆内点位 | 入口、展厅、史迹等有独立位置或导览价值的对象。入口持独立 ID，并沿所在馆区取得行政归属。一个实际入口服务多个馆区时，各馆区选择引用该入口。 |
| 展览和历史资料 | 展览的布展关系选择实际馆区及适用入口，讲解选择所依据的历史事件、档案和素材。同一条资料也可被城市介绍或专题引用。 |

行政区可选择主管行政区。馆区可选择行政区和主要运营机构。馆内点位可选择物理所属馆区。服务入口、布展和专题成员是独立关联。后端按各国允许的父子类型校验，拒绝循环和非法跳级。归属变更遵循以下作用域规则。

### 02.1 归属变更与授权

| 视图或动作 | 权限与归属依据 |
| --- | --- |
| 从未发布对象的草稿 | 以已保存归属为当前范围。变更成功后，按新的已保存归属读取和编辑。 |
| 已有发布记录的草稿与当前视图 | 以最近一次审批生效的归属为当前范围。待审草稿可以指向新范围，普通撤下或暂停也保留此前的管理范围。待审期间公开路径仍沿旧父链。 |
| 历史与候审 | 历史要求同时具备当前范围和快照范围的读取权限。跨范围候审正文要求同时可读冻结的源与目标范围。涉及译文时，各范围都须通过语种读取校验。审核摘要沿第 04 节的有限展示规则。 |
| 变更归属、提交和批准 | 先取得当前对象读取权，再分别校验源、目标范围的相应动作。修改归属校验两侧 `records.edit`，提交校验两侧 `publication.submit`，批准校验两侧 `publication.review`。对语种与对象的权限继续按第 04 节单条授权判断。 |

变更请求只修改归属字段，使用当前共享修订。当前公开版本存在时，跨国迁移先完成普通撤下。仍有受影响的生效子树或保持公开的必需引用时，先撤下或重新关联相关对象。提交时冻结源和目标父链，批准时在第 08.2 节规定的事务中再次核对范围授权、父链、修订和依赖。变更获批后切换生效归属及管理范围。单侧授权、调用方旧修订和申请失效均须按接口契约返回对应结果。 [归属请求与样例](contracts/v1/relocation.schema.json) · [审批条件](全球旅游后台首版接口契约.md#0512-发布命令候选与覆盖条件)

### 02.2 国家配置核验

国家的层级、邮编规则和官方语种归同一国家记录。M2 从空库先新建国家，再完善配置草稿和各项来源。具有该国家范围读取和目录核验权限的人员提交配置核验。通过后生成独立配置版本并成为录入时的当前配置。行政区层级选择、地点邮编及覆盖配置均从该版本读取。经核验明确不启用下级层级时，允许地点直接归国家。配置核验不启动 M4 的公开发布。

首次核验前，下属辖区录入须等配置核验。修改草稿或核验驳回时沿用上次已核验配置。核验使用当前草稿修订，检查层级关系、登记语言、邮编格式和来源，事务内切换配置版本并保留审核记录。同一国家的同一草稿修订只接受一个核验决定，下一次核验须基于修改后的新修订。核验、行政区创建和迁移、导入及地点邮编写入都持有相关国家的永久记录锁，在锁内读取当前配置与核验状态。涉及多条授权或业务记录时按第 08.2 节统一加锁顺序。配置变更若会使已有行政区父子关系非法，须先处理受影响的归属。新的邮编规则用于后续编辑，既有存档值留待复核。 [国家配置契约](contracts/v1/country-configuration.schema.json)

馆方资料显示，两个相邻展区拥有不同入口，利济巷分馆位于另一处。该案例可用于验证机构、到访地点、入口和展览各自的归属。 [馆方展区说明](https://www.19371213.com.cn/information/notices/202607/t20260707_5872161.html) · [馆方分馆介绍](https://www.19371213.com.cn/information/news/201802/t20180227_2248243.html)

## 03 数据维度、唯一来源与字段规则

| 后台模块 | 维护范围 |
| --- | --- |
| 基础数据 | 国家和行政区、地址、坐标、边界、机构、地点、馆内点位、交通站点。住宿、餐饮、购物、公共服务等地点通过类型模板扩展。 |
| 字典与标准 | 语言、币种、时区、度量衡、供电规格、插头插座、地点分类、交通方式、设施和无障碍类型。每项有稳定编码和中英文名称。 |
| 地区适用规则 | 国家及下级辖区适用的标准、币种、时区、通信和支付说明等。用电规格以电压与频率的有效组合录入，辖区通过选择建立关联。地区覆盖按规则组独立生效，供电规格和插座类型分别解析。 |
| 信息中心 | 区域和城市介绍、历史事件、遗产、文化礼仪、常设展、导览、到达说明、旅行指引及求助资料。可按业务目录检索，也可从地理树打开同一条记录。 |
| 来源与素材 | 官方网页、档案、地图数据、图片、音视频、字幕、替代文本和授权信息。内容通过选择引用来源和素材。 |

每个字段定义值类型、语言策略、唯一维护入口、关联目标、必填条件和校验规则。表单和后端校验共用这套定义。

| 字段属性 | 维护和保存规则 | 示例 |
| --- | --- | --- |
| 共享值 | 整条记录填写一次。 | 邮编、门牌、经纬度、日期、电压。邮编按字符串保存，格式和必填性按国家配置。 |

| 选择关联 | 通过筛选或树选择器建立关联，保存稳定 ID。 | 所属行政区、运营机构、交通站点、字典项、史料和素材。 |
| 派生展示 | 根据事实、引用和显示语言生成。 | 地理路径、展示地址、日期格式和单位名称。 |

首批迁移前逐字段记录权威对象、字段属性、关联目标及基数、来源、空值语义和旧字段处置。入口名称和坐标由入口维护，馆区地址和邮编由馆区维护。现有点位的营业时段、预约标志和开放、预约说明各自核对：结构化规则由适用馆区的参观规则持有，说明可引用该规则。时效性规则随对应旅程能力接入。 [现有点位字段](../front-end/src/types/point.ts#L8) · [现有绑定字段](../front-end/src/store/useTourismInfoBindingStore.ts#L26)

## 04 人员语言权限与全局界面

人员管理配置主语言、支持语言、角色和数据范围。主语言必须属于账号已授权的语种，且该语种的后台界面文案已就绪。内容维护可以先开放新的语种，待其界面文案齐备后再允许设为主语言。登录后由后端下发会话配置，菜单、表头、按钮、错误提示、列表和选择器统一使用主语言。

账号 A 的主语言是 `en`，支持 `en`、`zh`、`ja`。A 登录后看到英文界面，编辑纪念馆时看到三个语言维护区。邮编、坐标和行政区关联各出现一次，共享事实的修改权限由业务角色和数据范围决定。

服务端在读取、编辑、搜索、导入、导出、审核预览和历史查看时校验语言权限。未授权语种以任务状态和完成情况提示。调整授权后，后续请求按最新权限执行，已有译文继续归原记录。会话应提供显式主语言，替换原型依赖语言数组首项和浏览器状态的逻辑。 [当前账号语言逻辑](../front-end/src/store/useAuthStore.ts#L20)

| 动作 | 服务端授权条件 |
| --- | --- |
| 编辑共享事实 | 同一条授权同时覆盖对象范围和共享字段编辑动作。 |
| 阅读、编辑、导出或校对译文 | 同一条授权同时覆盖对象范围、语种与具体动作，且语种在账号支持清单中。 |
| 审核整版发布或撤下 | 有该对象范围的发布审核权限。校对结果可作为审核依据，译文正文按审核人的阅读权限显示。 |
| 配置人员语言或权限 | 有人员管理权限，并在可管理的对象范围内。编辑、校对和发布权限按相应授权判断。 |
| 紧急暂停公开 | 有该对象范围的紧急处理权限，并记录原因。 |

同一条授权必须满足一次操作的全部条件。「中国中文编辑」与「日本英文编辑」合在一起仍只能编辑各自授权范围。撤销授权使用原会话再次请求时立即生效，搜索、筛选、选择器、正文插入译名、预览、历史和已生成导出的下载均执行最新过滤。若收回主语言，须在同次保存中指定有效的替代语言。撤权与审核串行更新同一授权记录。敏感写入提交前复核权限修订号，并持有该授权记录的锁直至事务提交。撤权前有效的校对记录继续可审计，未完成的任务重新分配。

该授权记录是每个账号长期存在的权限修订记录。账号停用、角色、管理范围或语言授权变化时，同事务推进受影响账号的修订号。涉及多个账号时按固定顺序获取锁。

## 05 翻译协作与中英文发布要求

1. **全局必备语言为 `en` 和 `zh`。** 后台基础文案先覆盖两语。所有对外展示的可翻译字段，以及必要关联的名称和标签，都要有完整且已校对的中英文。可选字段一旦纳入发布，同样适用。
2. **不同语言可以分别保存。** 每条译文按「对象 ID + 语种」唯一保存。共享字段和各语种各有修订号。两个账号可分别提交中英文，同一语种发生并发修改时提示冲突。
3. **翻译校对绑定版本。** 译文记录对应的原文修订号。原文语义变更时，将受影响的译文标为待复核。上一版继续生效，直到新的中英文版本齐备并通过审核。
4. **当地官方原文保留出处。** 地名、地址、机构名称和入口标识可供现场核对。与已维护的正式中英文名称一致时直接引用同一记录。其他语种按业务分批补充，复用同一套事实和关联。

中英文可由不同人编辑和校对。发布审核人依据该版本的逐语种校对结果做决定，预览文字遵守自己的语言权限。当前通过同一份文本填补缺译的记录，在迁移时进入待核对队列。 [当前译文补齐逻辑](../front-end/src/pages/InfoCenter/TourismInfo/index.tsx#L43)

校对记录绑定原文修订号与对应语种修订号。候审版明确列出将展示的字段、直接引用版本和语言。纳入发布的可翻译字段及必要的引用译名同时校验中英文；尚未齐备的可选字段可保留在草稿。扩展语种沿用与本版原文一致、已校对的译文。若已生效的扩展语种本次缺少合格译文，提交前显示将从新版本移除及其影响，由发布审核明确确认。正文和关联译名渲染按语种读取对应版本，后台缺译时可显示编码，明确登记且可溯源的当地官方原文按对象权限提供现场对照。

| 景点游览 | 正确的馆区与入口、到达路线、参观指引、常设展、历史讲解和现场礼仪。 |
| 异常与返程 | 遗失证件、就医和求助、交通中断、离境手续、行李、转机及返程步骤。 |

每条关键指引交代做什么、去哪儿或打开哪个渠道、准备什么、现场会看见什么。旅客用自己读得懂的本国官方语言理解步骤，再用目的地官方原文识别标牌、填写字段或向工作人员出示地址。有多种官方语言的出发市场，按旅客所选语言分别计算覆盖。

覆盖状态从当前生效资料计算。关键译文、现场原文、操作步骤和需要核验的来源齐备后，该组合才标记就绪。日语等扩展语种可逐条补齐，再按旅程验收。

为每个旅行场景配置必备步骤、适用条件和所需资料类型。出发市场用于组织语言覆盖。证件签发地、旅行目的、出行日期和途经地点用于匹配对应规则。每一步返回已核验、缺信息、缺译、待复核或已核实不适用及原因。至少有一项适用的必备步骤且全部适用的必备步骤已核验才标记就绪。明确不适用要有证据，缺少适用条件显示待复核，缺少场景配置显示未配置。

目标是让只读得懂所选出发市场官方语言的旅客逐步完成关键操作。场景首次标为完整覆盖前，由该语种的校对人员用已发布内容走查关键步骤，核对能否判断适用条件、找到正确地点或渠道、准备所需材料并识别现场标记。任一步需要自行翻译才能继续，或无法仅凭指引确定下一步，均记录为对应缺口。

首版按读取时的生效版本及有效期计算就绪状态。国家规则变更、扩展语种撤下、资料过期或安全撤销时，受影响旅程同步重算。其它国家的结果和馆区自身版本仍按各自规则计算。后续如保存覆盖计算结果，读取时检查依赖版本和最早失效时间，失配就显示待复核。

## 07 来源、导入与纠错

- **证据关联到具体事实。** 行政归属、地图位置、场馆名称、历史论述和图片授权可各自引用不同来源。记录发布机构、出处、采录或核验时间。时效资料另记生效范围和日期。
- **导入先预览再入库。** 按「来源系统 + 实体类型 + 外部编号」匹配已有记录，预览新增、更新和冲突。同名或坐标接近的对象交人工核对。重复导入同一批数据应得到相同结果。
- **更正走版本流程。** 保留导入批次、差异和操作者。行政归属变更、记录合并和标准停用先列出引用影响，再执行更正或重新发布。历史版本继续保留当时的资料和证据。

多个外部编码经核验可映射到同一个业务 ID。导入保留来源版本、外部编码、目标 ID 和人工采用依据。同一地点的坐标、父链或名称有冲突时，待核记录留在暂存区，正式字段继续使用已核验值。几何资产与可编辑主数据通过 ID 关联，首批用南京和第二国样本建立映射，提交前对账实体、父链、几何引用、语言状态及异常项。当前地图与业务省份编码存在中文名兼容匹配，这类记录需转为显式映射后再进入正式链路。 [现有编码兼容逻辑](../front-end/src/pages/PublishCenter/index.tsx#L128)

## 08 节点版本、发布与取消发布

状态主线为 **草稿 → 提交并冻结待审版本 → 审核通过 → 切换生效版**。驳回时草稿可继续修改。已发布节点可以同时维护下一版草稿。

### 08.1 共享资料与版本读取

字典、机构、展览、历史资料和素材各自维护修订版本，目录状态为草稿、核验通过可引用、停用。选择器提供可引用的版本。目录停用后，含该引用的草稿和待审申请在提交或批准时均重新校验，既有生效版仍可以读取原核验版本。关闭对象当前公开入口按普通撤下处理。需要让所有引用方停止展示某个确切版本时，按第 08.4 节处理版本撤销。

首批区域、馆区和具备独立位置的点位是发布目标。区域发布采用适用规则组，馆区通过选择采用已核验的独立内容版本。目录自身的核验记录可供选择，确切版本可独立撤销；涉及公众展示的变更由引用它的发布目标提交。 [管理前端流程](全球旅游后台首版管理前端规格.md#06-发布工作区与覆盖)

| 关系 | 生效版与历史读取方式 |
| --- | --- |
| 地理身份 | 保存稳定 ID。当前地理导航读取已生效父链和当时有效的地理身份名称版本，上级节点正文可独立撤下。提交时冻结本次候选父链、名称和名称版本；其中归属迁移候选使用拟生效父链。 |
| 直接引用 | 待审版冻结所选史料、展览、素材及字典的确切版本。常规修订可反查受影响地点，地点重发时选用新版本。 |
| 上级规则 | 当前展示读取已生效父链上最近一层适用的对应规则组。历史审核预览以提交时的一致性读取快照为准，冻结路径节点名称版本、规则取值辖区与规则版本。生效记录关联该审核快照、内容版本和生效时间。 |

规则组区分未配置、未来待生效、明确不适用和已撤下或过期。未配置可以继承，未来待生效维持当前结果，明确不适用须记录依据，已撤下或过期显示待复核。撤下后恢复继承必须通过明确的生效操作。某地只覆盖插座类型时，供电规格仍按自己的规则组解析。

管理端规则列表并列显示本辖区草稿与当前生效结果。管理生效预览和旅客详情按相同规则获取各组状态、采用辖区与版本，分别按权限投影。历史审核保存审核当时的各组状态与采用版本，前端直接展示该快照。请求语种缺少必要规则译文时对应组待复核，不混入其他语种。 [生效规则请求、响应和 AC-06 样例](contracts/v1/resolved-rules.schema.json)

管理当前生效预览和旅客详情展示已生效父链。发布草稿预览展示本次候选父链，恢复预检展示当前合法归属的父链。冻结申请与历史版本展示当时采用的名称和版本，后续改名和迁移不回写快照。审批校验父链稳定 ID 与授权范围，独立的名称修订不使候审失效。根对象没有父链。受限祖先保留各自的匿名位置。派生地址和结构化引用只使用获准的名称与标识。规则出处身份受限时，对应组返回匿名的不可用状态。正式原文按自身的公开或读取授权提供。 [父链结构](contracts/v1/geographic-path.schema.json)

### 08.2 常规发布与取消发布

| 业务动作 | 后端规则 |
| --- | --- |
| 提交发布 | 根据节点 ID 读取真实父链，校验本节点的必填数据、译文、来源及必要引用。冻结本节点资料和审核时选用的直接引用版本。同一节点最多一条待审操作。 |
| 审核生效 | 审核以冻结版本 ID 为准。事务内复核必要引用和预期生效版，切换唯一生效版本，并写入审计记录。相同请求标识和相同内容的重试返回已有结果。 |
| 读取上级资料 | 景点自己的介绍按本节点发布版本展示。用电等上级事实沿地理树读取权威辖区的当前生效规则。国家规则更新后，继承该规则组的景点读取新规则，本地覆盖按辖区状态解析。 |
| 取消发布 | 列出把目标作为必需引用的已发布资料，先处理替换或撤下，再关闭目标当前公开入口。保留地理身份、草稿、审核意见和历史。其它资料已获准内嵌的可选冻结引用仍可展示，对已撤下目标的入口链接显示为不可用。 |

生效引用索引由发布版本生成，记录引用方生效版本、关系字段、目标 ID、适用的版本 ID 和关系类型，支持按对象与版本反查。依赖边按第 08.2.1 节归类。地理身份独立校验父链，公开依赖通过关系类型和单向层级阻断循环。目录停用、对象暂停及确切版本撤销共用下列事务规则。

1. 从冻结候审版和预期生效版取得新旧必需依赖和直接引用的所有者。按稳定对象键排序，对发布对象及相关目标的永久记录加锁。权限修改先锁相关授权记录，业务写入也按该顺序检查授权，再锁业务对象。
2. 采用 `READ COMMITTED`，锁齐后使用新的查询重读实际生效版、目录及确切引用版本状态、反向必需依赖。若生效版或锁集合已变，释放锁并重算后重试。影响清单在确认页展示，执行时按当前依赖重新检查。
3. 生效版本、必需依赖和审计在同一事务提交。所有直接引用的索引也在该事务同步。会改变上述状态的发布、撤下、停用、回滚与批量更正走同一服务入口。 [PostgreSQL 行锁与加锁顺序](https://www.postgresql.org/docs/current/explicit-locking.html#LOCKING-ROWS)

发布检查由后端执行。同一个馆区从地理树、信息中心或发布中心提交，得到相同结果。当前发布逻辑以页面选中的层级拼接校验，状态保存在内存中，实施时迁移至数据库事务和版本记录。 [当前发布校验](../front-end/src/pages/PublishCenter/index.tsx#L552) · [当前发布状态](../front-end/src/api/publish.ts#L4) · [PostgreSQL 事务文档](https://www.postgresql.org/docs/current/tutorial-transactions.html)

#### 08.2.1 引用关系与公开结果

| 关系字段 | 发布采用方式 | 普通撤下、暂停或目录停用 | 确切版本撤销 |
| --- | --- | --- | --- |
| 行政区 `parentId`、馆区及独立站点 `areaId`、馆内点位 `parentPlaceId` | 地理身份稳定 ID，采用当前父链。冻结审核保留名称版本。 | 上级正文下线不关闭子节点，仍使用有效地理身份。 | 只撤销上级正文版本时不变更地理身份。身份无法继续公开时，通过归属处理或撤下受影响对象。 |
| 馆区 `entranceIds`、展览 `entranceIds` | `link-only`，导航链接按当前可公开版本读取。 | 目标撤下或暂停后链接不可用。只有此关系时允许撤下。 | 当前版本仍可公开则链接继续有效。只有被撤销版本可用时，旧链接与从该版取得的名称不再返回。 |
| 已纳入生效包的到达指引 `entranceId`、`stopId` | `public-required`，按当前可公开目标读取。审核保留当时的目标证据。 | 普通撤下若会破坏任一当前公开引用方，则阻止并提示先替换或撤下引用方。紧急暂停使受影响引用方不可公开。 | 目标若还有符合要求的当前版本则继续可用。依赖无法满足时，受影响引用方不可公开。 |
| 到达指引 `transportModeId` | `frozen-required`，冻结所选核验字典版本。 | 已发布包继续使用获准的版本。停用影响新的候选。 | 撤销采用版本使该节点不可公开；撤销其他版本不影响它。 |
| 馆区 `organizationId`、`contentRefs`，正文史料 `historicalRecordRefs` 和图片 `mediaRefs` | `frozen-optional`，冻结选用版本。运营机构是维护必填关系，可公开的名称作为单独信息块。 | 已发布包可继续显示已有许可的片段。跨页入口仍按自己的公开资格处理。 | 移除采用的对应片段及由它提供的旧链接、媒体和替代文本。其他片段继续可读。 |
| 辖区规则 `itemIds` | `rule-required`，按规则版本冻结采用的字典项。 | 已生效规则仍按其许可及适用期读取。 | 对应规则组待复核，未显式恢复前不自动向上继承。其他组独立。 |
| 来源 `sourceIds`、正式原文 `sourceId` | 已发布字段保留核验时采用的证据版本。必备事实的证据关系为 `evidence-required`。 | 已核验且仍有许可的依据可继续使用。 | 仅撤销的证据从公开输出移除。同一事实若另有已核验并采用的有效证据则保留。必备事实缺少有效依据时节点不可公开，选发事实缺少依据时移除该片段。 |

正文中通过 ID 选择的引用继承所属字段的关系类型。到达指引作为可选块纳入生效包后，其中保持公开的依赖适用于整个包。该指引若因确切版本撤销而被移除，仅由它产生的依赖不再阻止其他对象普通撤下。

预检按本次动作比较同一快照内的公开结果，沿公开资格变化传播，纳入直接和间接受影响的生效对象。已不可用且结果没有变化的分支停止传播，同一对象的同类结果合并。影响清单只显示获准对象，汇总标记只计存在实际变化的受限项。执行时锁定本次可能改变资格的对象，并按第 08.2 节顺序重读依赖，锁集合变化时重算。 [影响检查与撤销样例](contracts/v1/publication-dependencies.schema.json)

### 08.3 生效版读取契约

生效版只读接口使用独立响应模型，按允许公开的字段清单输出生效 ID、显示名称和内容、必要的当地原文及可用关联。草稿、审核意见和内部附件由管理接口在授权范围内读取。后台服务端以管理预览和内部读模型测试验证生效规则。客户端服务阶段再提供匿名读取，与客户端前端共同验收。

后台生效预览、历史、搜索和导出都按账号最新语言权限过滤，包含正文中插入的译名及选择器结果。仅有英文权限的账号请求中文读模型时，服务端返回无权访问或该语种的完成状态。明确登记且带来源的当地官方原文按对象权限提供。

生效详情、搜索结果、媒体和受控导出下载共用公开资格校验。搜索和索引可以提供候选，返回结果时复核当前状态。受控下载每次交付前复核版本和许可，撤下时吊销已有可控链接；已交付静态副本登记召回。

### 08.4 紧急暂停、版本撤销与恢复

对外内容证实有误或失去使用许可时，有权限的人员可以暂停对象公开或撤销确切版本，并记录证据、理由、操作者和影响清单。直接引用该版本的资料立即排除被撤销内容。撤销影响必需字段时，对应资料对外标为不可用。可公开的必需依赖沿链路复核，受阻资料保留生效指针和历史供处置。

紧急动作也锁定目标的永久对象记录，并按确切版本反查。某资料已发布 v2 时，仍可撤销被其它对象引用的 v1。撤销先提交时，引用 v1 的待审申请生效失败。发布先提交时，撤销提交后统一限制受影响的公开读取。发布 v3 或恢复对象公开资格，都不会解除 v1 的撤销记录。

对象同一时刻只有一个当前暂停事件。新暂停接替当前暂停，所有事件保留历史。暂停恢复从旧版内容创建新的发布申请，按现行来源、素材许可、中英文校对、地理归属和依赖重新校验。恢复申请记录当前暂停事件、预期公开状态修订和预期生效版。审核时锁后重新比对状态，出现更新的暂停事件或版本变化时退回重审。恢复生效与解除对应暂停在同一事务提交，已撤销的确切版本保留撤销记录。普通撤下后的重新上线走常规发布。历史版本和审计保留在授权管理视图中。

**管理后台前端 → 管理后台服务端 → 客户端前端 → 客户端服务。** 上一段完成门槛后才能进入下一段。每段内部可按独立工作并行。M0–M5 是管理后台服务端内部顺序，前端规格引用这些编号时仅用于定位对应功能。

| 顺序 | 开发交付 | 完成门槛 |
| --- | --- | --- |
| 1. 管理后台前端 | 沿现有管理端完成登录与人员、地理与资料、翻译校对、发布、覆盖工作区。按[管理前端规格](全球旅游后台首版管理前端规格.md#01-页面入口与实现归属)交付。 | 不依赖后台服务即可用契约夹具复跑[第一段验收](全球旅游后台首版管理前端规格.md#073-浏览器用例)。 |
| 2. 管理后台服务端 | 按 M0–M5 实现真库、身份、资料、翻译、发布、覆盖和审计，将管理后台前端切到真实接口。 | 双环境与管理后台真库闭环通过。生效读模型、撤下与恢复通过管理预览和内部测试。 |
| 3. 客户端前端 | 按公开读取契约完成旅客检索、详情、语言切换、当地原文及关联展示。 | 用公开契约夹具运行关键路径，验证中英文、缺译、不可用状态和服务失败。 |
| 4. 客户端服务 | 提供面向旅客的公开只读服务，接通客户端前端。 | 匿名检索、详情与媒体通过实际联调，管理后台发布、撤下、确切版本撤销在客户端生效。 |

每段按开发规格第 07 节记录实跑证据。首版管理后台在第二段收口，公开交付在第四段完成。 [阶段验收证据](全球旅游后台首版开发规格.md#07-阶段交付与验收证据)

### 09.3 管理后台服务端 M0–M5

| 阶段 | 实施工作 | 完成门槛 |
| --- | --- | --- |
| M0 环境和样例 | 接入后端启动配置，交付数据库迁移、固定测试种子、健康检查和测试命令。 | 在空的 `dev` 和 `test` 数据库分别复跑，环境数据隔离，重复迁移和种子装载结果一致。 |
| M1 语言和人员底座 | 语言字典、人员主语言与授权、会话接口、全局文案、通用语言表单和后端鉴权。 | 两个不同语种的账号可协作，越权读写被拒绝，主语言全局一致。 |
| M2 基础数据与选择关联 | 建立行政区、字典、机构、馆区、入口、站点及用电标准关系，接入基础译名、搜索选择器、来源映射和正式导入预览。 | 纪念馆机构关联多个馆区，跨来源重复导入保持稳定 ID，测试中的两国可共用同一标准条目。 |
| M3 内容和翻译闭环 | 录入馆区简介、常设展、到达说明、史料和素材。实现逐语种保存、校对、版本标记和预览。 | 一个邮编、一组坐标、一套关联对应真实中英文，缺译和待复核状态明确可见。 |
| M4 真实发布与取消发布 | 实现发布申请、单级审核、生效版本、引用影响、撤下、紧急暂停和审计。交付内部发布读模型与授权预览。 | 通过管理端和真库验证跨节点并发、管理导出旧链接撤销、版本恢复和服务重启。 |
| M5 迁移和覆盖验收 | 按批对账并切换数据库读写，接入旅程语言就绪检查，演练备份恢复。 | 两国样例完成后台全流程，结果可复查。正式启用前验证覆盖失效和恢复后的发布、权限与审计状态。 |

每个业务模块切到后端时同步切换读写，前端本地状态保存输入草稿和界面状态。 [接口契约](全球旅游后台首版接口契约.md) · [阶段验收证据](全球旅游后台首版开发规格.md#07-阶段交付与验收证据)

恢复先在隔离环境完成。备份记录对应的审计水位。恢复后用与备份独立保留的操作日志核对水位之后的发布、撤销和授权变更，完成重放或人工对账，再验证账号权限、父链、生效版本、引用和旧链接。无法确认的操作保持隔离，正式流量在校验完成后切换。

## 10 首版验收用例

| 编号 | 反例或操作 | 通过条件 |
| --- | --- | --- |
| AC-01 | 两国只导入最小样例，发布一个馆区，行前资料尚未录入 | 可读取馆区中英文生效版，全旅程仍显示缺口。重复导入实体数量和 ID 一致。 |
| AC-02 | 同机构有两个馆区，两个馆区共用一个实际入口 | 机构和入口各只有一个 ID，各馆区地址各自维护。译名、搜索、路线和地图都能定位对应对象。馆区待审迁移继续沿原路径展示。 |
| AC-03 | 账号主语言为 en，分别授权中国中文编辑、日本英文编辑、中国日语阅读、导出与校对。先验证日语预览、导出和校对可用，再撤权并使用原会话重试 | 中国英文编辑被拒绝。撤掉日语授权后，未授权预览、校对和旧导出下载被拒绝。撤权和审核两个提交顺序分别验证，已合法校对的版本保留审计。 |
| AC-04 | 修改原文并同时保存两个语种，再提交缺英文或使用过期日语的候审版 | 两个语种独立保存。中文或英文缺失及校对待复核阻止生效。扩展语种需匹配本版原文，移除会先提示并更新覆盖。 |
| AC-05 | 地图和业务数据给同一行政区不同外部编码，又给同一地点冲突坐标 | 外部编码经核验映射到同一业务 ID。冲突留在暂存区，正式坐标保持已核验值。两次导入对账通过。 |
| AC-06 | 馆区候审版先冻结，国家后更新用电规则与地名译名。辖区的插座例外依次经历有效、过期和显式恢复继承 | 继承组读取该国新规则，另一国保持原规则。历史审核显示提交时的名称、辖区和规则版本。插座组依次采用地方覆盖、标记待复核、恢复上级规则，供电组独立解析。 |
| AC-07 | 两个数据库会话交错发布 B、撤下 A、把 B 的必需引用从 A 换到 C | B 先发布时 A 普通撤下受阻。A 先撤下时 B 发布受阻。B 完成切换后 A 可撤下。模拟失败时生效版、引用及审计回滚。 |
| AC-08 | B 已获准内嵌 A 的 v1 可选片段。普通撤下 A 后访问旧入口、搜索、媒体和导出，再撤销 v1。仅英文账号请求后台中文生效预览与历史 | A 自身公开入口关闭，B 继续展示获准的内嵌片段，撤销 v1 后 B 停止展示该片段。只读响应只含获准发布字段，后台中文译文和旧下载按权限拦截，独立公开的其它生效中文资料仍可由测试客户端读取。 |
| AC-09 | A 当前为 v2，B 仍引用 A 的 v1。交错撤销 v1 与批准 B。另在针对暂停 S1 的恢复待审时再提交暂停 S2 | B 后批准时失败，B 先发布时受影响公开内容立即不可用。旅程覆盖同步降级，发布 v3 后 v1 仍保留撤销。S1 的旧恢复申请无法解除 S2。 |
| AC-10 | 在紧急撤销和改权限之前备份，然后恢复该备份 | 隔离环境对账或重放水位之后的操作。验证权限、历史、引用、生效版和旧链接。撤销继续生效后才切换流量。 |

第一条完整链路用南京纪念馆验收。第 09 节决定开工顺序，开发规格第 07 节决定每项 AC 在哪一段收集证据。跑通语言权限、一次维护、多处引用和真实发布后，再按批扩展国家、地点类型及旅行场景。 [阶段验收证据](全球旅游后台首版开发规格.md#07-阶段交付与验收证据)
