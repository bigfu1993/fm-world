# 基础数据与信息中心收敛调整范围

更新时间：2026-07-03

## 调整目标

本次调整围绕两个问题展开：

- 省份和城市此前使用同一套特色维度，层级差异不明显。
- 信息中心模块较多，部分模块存在同类信息分散维护或历史模块冗余。

调整后的原则是：信息中心维护可复用资料，基础数据只绑定资料 id；省份表达跨城市区域结构，城市表达城市内体验场景；冗余信息中心模块应归并到已有资料模块中。

## 基础数据调整范围

### 省份信息绑定

省份特色从通用“地理、人文、宗教、饮食、历史”调整为区域级维度：

- 区域地貌：山海、湖泊、河谷、自然带等跨城市地貌结构。
- 文化圈层：民族、民俗、手作、区域性节庆等跨城市文化圈。
- 遗产集群：宗教遗产、遗址群、古道、历史走廊等区域资源集合。
- 风味体系：区域菜系、食材产地、跨城市美食主题。
- 季节活动：花期、雪季、丰收季、节庆季、跨城市活动窗口。

省份仍保留：

- 信息中心“交通”模块绑定。
- 建议停留天数。
- `customSupplement` 自定义多语言补充。

### 城市信息绑定

城市特色从通用“地理、人文、宗教、饮食、历史”调整为城市体验级维度：

- 城市街区：核心片区、滨水街区、商圈、步行街等游客活动空间。
- 城市生活：市集、社区活动、手作店、本地生活方式。
- 餐饮场景：餐饮街区、餐厅聚集区、夜宵区域、游客饮食提示。
- 城市遗产：老城、历史建筑、工业遗产、殖民街区、城市更新背景。
- 城市活动：展演、夜间活动、市集、体育赛事、临时城市活动。

城市仍保留：

- 信息中心“交通”模块绑定。
- 建议游玩天数。
- `customSupplement` 自定义多语言补充。

## 信息中心收敛范围

### 单维度基础字典

语言是独立单维度基础字典，继续使用语言管理页维护。

### 单维度资料模块

以下模块统一按 `code / 名称 / value / 补充 / 操作` 维护，并复用 `SimpleInformationPage`：

- 时区
- 气候
- 支付
- 交通
- 交通规则
- 驾照
- 入境政策
- 海关禁限
- 服务平台
- 网络

### 多维度类型资料

以下模块参考国标模式，使用“类型列表 + 类型下条目”的结构：

- 国标：电压、插头、电话等类型。
- 文化：文化、习俗、宗教等类型。
- 旅游资料：按层级和类型维护省份、城市、点位、地标资料。

后续如果某个单维度模块开始出现多个自然分类，应优先升级为多维度类型资料，而不是新增并列模块。

### 复合资料

注意事项保留复合结构：

- 安全概况
- 风险区域
- 夜间逗留时间

这类资料不是简单字典，也不是单纯类型列表，适合继续以复合字段维护。

## 已整合模块

服务信息模块已从信息中心入口中移除：

- 租车规范归入交通/驾照相关资料体系。
- 货币支付归入支付模块。
- `/info-center/service-info` 旧路由保留，跳转到 `/info-center/traffic`。
- `/info-center/currency-payment` 旧路由保留，跳转到 `/info-center/payment`。
- `serviceInfo:manage` 权限入口移除。

## 后续建议

- 将旅游资料也逐步抽象为“类型列表 + 类型下条目”的显式类型管理能力，避免后续继续通过代码硬编码类型。
- 将注意事项评估是否升级为多维度风险资料，例如治安、食品、水、自然灾害、夜间活动等类型。
- 将交通模块补充“租车规范”类条目，用以承接原服务信息中的租车说明。
