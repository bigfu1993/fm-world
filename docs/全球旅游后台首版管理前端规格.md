# 全球旅游后台首版管理前端规格

本规格定义第一段「管理后台前端」的页面、操作、请求时序和验收。业务规则和 AC 由实施方案维护，字段类型和 HTTP 契约沿用既有权威章节。本文中的 M1–M5 用于对照第二段服务端能力。第一段在真实路由上使用隔离夹具验收，第二段用同一组页面接真实接口。 [实施顺序](全球旅游后台首版实施方案.md#09-实施顺序与完成门槛) · [字段定义](全球旅游后台首版开发规格.md#031-首批表单和传输字段) · [HTTP 契约](全球旅游后台首版接口契约.md#051-管理资料与发布接口)

## 01 页面入口与实现归属

沿用现有 React、Ant Design 和布局。所有列表统一采用「标题和主操作 → 筛选 → 结果 → 分页」；记录详情以抽屉承载，发布与覆盖保留整页工作区。桌面编辑区保持左列表或地理树、右详情，360 CSS 像素宽时切成列表与全宽详情，各区保留返回与当前操作。

| 编号 | 路由与稳定定位 | 页面与复用入口 |
| --- | --- | --- |
| UI-01 | `/login`、`/dashboard` | 登录、导航外壳、后台入口。复用 `Login`、`Dashboard`、`BasicLayout`。 |
| UI-02 | `/system/admin-users?id={accountId}&panel=profile` 或 `panel=grants`。`/system/roles` | 人员、授权和角色预设。复用 `System/AdminUser`、`System/Role`。 |
| UI-03 | `/master-data/countries`、`/master-data/provinces`、`/master-data/cities`，以 `id` 打开详情 | 国家、行政区、受限地理树、配置与边界。复用 `MasterData` 的现有页面入口。 |
| UI-04 | `/master-data/points?view={view}&id={id}` | 地点、机构、来源和导入依次使用 `places`、`organizations`、`sources`、`imports`。默认 `places`。 |
| UI-05 | `/info-center/standard-specs?view={view}&id={id}`、`/info-center/languages` | 字典用 `items`，地区适用规则用 `rules`，默认 `items`。另有语言目录。 |
| UI-06 | `/info-center/tourism-info?ownerId={id}&type={type}&id={id}&locale={locale}` | 馆区介绍、展览、史料、到达指引及逐语种编辑。 |
| UI-07 | `/publish-center?view={view}&targetId={id}&requestId={id}&versionId={id}&panel={panel}` | 对象用 `records`，队列用 `queue`。默认 `records`。`panel` 取 `draft`、`request`、`effective`、`history`，新打开对象默认 `draft`。 |
| UI-08 | `/publish-center?view=coverage&panel={panel}&id={id}` | `check` 为覆盖检查与走查，`scenarios` 为场景维护，默认 `check`。`id` 只用于场景详情。 |

带 `id` 的页以服务端稳定 ID 定位，刷新重查权限；清除详情参数后返回原筛选列表。筛选条件可进 URL，分页游标、口令、令牌、正文草稿和完整导出链接留在本次运行上下文。非法枚举参数回到授权范围内的默认页面；不存在或不可见的稳定 ID 显示统一的不可用状态。现有 `/master-data/landmarks` 作为地点入口的兼容路由；旧对象编号仅在有显式迁移映射时定位到新 ID。

未纳入首批闭环的旧信息模块保留路由兼容和明确的未启用状态。正式入口的可用菜单只出现本规格支持的功能。旧本地登录、发布和信息存储行为供迁移核对。 [现有路由](../front-end/src/router/index.tsx#L39) · [原型登录](../front-end/src/api/auth.ts#L1) · [原型发布](../front-end/src/api/publish.ts#L1)

| 实现边界 | 所属职责 |
| --- | --- |
| `src/router/`、`src/layouts/BasicLayout.tsx` | 路由、会话和菜单门禁、重定向、安全的返回位置与公共布局。布局不读取各页业务列表。 |
| `src/pages/` 对应页面 | 请求触发、编辑草稿、筛选、弹层和回执后的刷新。页私有组件留在所属页面目录。 |

| `src/store/useAuthStore.ts`、现有语言与主题入口 | 会话和主语言投影。会话以当前请求为准，运行中持有 CSRF 和就绪状态。列表、版本和授权回执归各页面查询。 |

## 02 全局权限、语言和操作状态

### 02.1 交互矩阵

菜单和直达路由共用同一入口权限映射。下表列的是入口条件，分隔的动作任一成立即可显示。切换标签时重新应用对应条件，没有获准的标签时显示无访问权。记录、语种和写操作使用对象响应的条件。

| 页面或入口 | 会话入口条件 |
| --- | --- |
| UI-01 工作台 | 有效会话。 |
| UI-02 人员、角色 | `accounts.read`、`accounts.manage`。 |
| UI-03 地理、UI-04 地点机构来源、UI-05 字典规则、UI-06 内容 | `records.read`、`records.edit`、`translations.read`、`translations.edit`、`translations.review`、`catalog.review`。 |
| UI-04 导入 | `imports.manage`。 |
| UI-05 语言目录 | `records.read`、`accounts.read` 或 `accounts.manage`。 |
| UI-07 对象与发布 | `records.read`、`publication.submit`、`publication.review`、`publication.restrict` 或 `translations.export`。 |
| UI-07 审核队列 | `publication.submit` 或 `publication.review`，详细行由服务端过滤。 |
| UI-08 覆盖、UI-08 场景维护 | 覆盖检查用 `coverage.read` 或 `coverage.review`，场景维护用 `coverage.manage`。选择对象仍取获准的地理与资料范围。 |

| 层次 | 前端输入与可见结果 |
| --- | --- |
| 会话与导航 | 启动先取当前会话。已登录页面使用 `primaryLocale` 渲染菜单、表头、按钮、组件、页面标题和 `html[lang]`；登录前用中文。会话 `allowedActions` 驱动模块入口，账号无可用菜单时保留账号区与退出。内容面板切换不改变界面主语言。 |
| 对象 | 页面允许进入后按对象接口的 `allowedActions` 决定编辑与审核入口。只有共享字段编辑权限才显示相应保存操作。保留当前值但缺少字段编辑资格时显示只读。由现有共享字段模板及响应选择可见字段。 |
| 语言 | 页签按 `localeActions` 返回的语种生成，优先排序主语言，再按 `supportedLocales` 顺序。只读显示授权内容；编辑、校对、导出动作按该语种分别判断。无访问权的语言区不创建 DOM、初始值、请求或浏览器缓存。只可读情况下也允许看到缺译状态。 |
| 译名和缺口 | 表格和选择器显示账号主语言的授权名称；缺译使用服务端给出的缺译状态与稳定编码。已登记的正式原文仅在有权限的原文区域展示。看不到具体问题时，用服务端汇总的状态说明仍有阻塞。 |
| 授权更新 | 回到浏览器标签页、页面重新激活或权限错误时重取会话，并在等待期间关闭受限内容。权限版本变化时作废旧读请求与旧缓存，重新查询当前对象。只保留重新验证后仍可编辑的草稿。账号身份变化或会话终止时清除全部受限数据。 |

### 02.2 标准请求和异常

| 条件 | 页面动作与验收结果 |
| --- | --- |
| 加载、空、失败 | 首次读取显示加载；成功且 `items=[]` 才显示空态。网络异常、`429`、`503` 保留重试入口；`429` 按 `Retry-After`。服务缺席时提示未连接，无法完成实际写入。 |
| `401` | 登录凭据错误留在登录页，保留账号名并清密码。已登录请求会话失效则清理数据、跳登录并保留同源受保护入口。重新登录后先验权再返回。 |
| `403`、`404` | 授权被收回或对象不可见时关闭对应受限内容、清理失权草稿并重取会话。`CSRF_INVALID` 更新会话和 CSRF 后由用户重新提交；幂等命令保留原键。生效版或语言不可用只更新生效预览，不清除有权编辑的工作草稿。 |
| `409` | 重新读取当前版本，仍获授权的已输入字段保留并与最新值对比。用户确认新条件后提交。候审状态及已生成回执以服务端为准。 |
| `422` | 根据返回的 `field`、`locale` 定位第一个可编辑问题；可见问题置于对应面板。不可见详情只呈现反馈摘要，不创建语言区。 |
| 写入超时 | 普通编辑读取最新值和修订，核对后由用户决定重试。幂等命令结果不明时用同键同请求重放，修改参数后使用新键。提交中锁定当前命令，页面离开不影响回执归属。 |

共享及逐语种表单各自提交。离开记录、关闭抽屉或切换对象时只在存在未提交变化的情况下询问去留；在语言面板间切换保留本次草稿。减少误操作时以接口允许的动作作为显示依据，以回执和再次读取作为状态依据。鼠标或键盘可完成主流程，错误聚焦到摘要或字段，关闭浮层后焦点回到触发处；桌面和 360 CSS 像素宽视口均检查。所有按钮状态使用文本或可访问名称表达。 [无障碍基线](https://www.w3.org/TR/WCAG22/)

## 03 会话与人员页面

### 03.1 UI-01 登录与工作台

- **结构。** 登录表单含账号、口令、提交和错误摘要。后台外壳包含主导航、当前位置、当前账号与退出。工作台只列当前可访问的业务入口，包含人员、基础数据、资料或发布与覆盖。暂无权限时显示一处说明。
- **流程。** 打开受保护路径 → `GET /api/sessions/current` → 按授权显示或跳登录。登录提交 `POST /api/sessions` 后应用主语言，优先进入获准的原目标，默认工作台。会话请求未返回时不显示受限内容。退出提交 `DELETE /api/sessions/current`，成功或会话已失效后清理并进入登录页。退出遇网络异常，先隐藏受限内容并提示重新尝试。
- **接口边界。** 会话状态拥有 `accountId`、`authzRevision`、`csrfToken` 与允许动作。写请求附 `X-CSRF-Token`。生产入口通过同源 Cookie，夹具用同一请求回执验收。进入工作台时不预取各业务模块列表。

### 03.2 UI-02 人员与角色

- **结构。** 人员列表显示用户名、状态、主语言、支持语种及操作；按用户名和状态筛选。新建对话框包含用户名、初始口令、所属范围、主语言和支持语言。详情抽屉分「资料」「授权」；角色页为只读预设列表，按预设展示动作。
- **新建和停用。** 输入归属范围与语种 → `POST /api/accounts` → 使用回执 ID 打开详情。编辑人员资料以该账号 `authzRevision` 提交 `PATCH /api/accounts/{id}`。主语言从支持语言与可用界面语言交集中选择；移除主语言时在同次保存提供替代项。已有归属只读。停用需确认，`LAST_ADMIN_REQUIRED` 保留原状态并解释原因。
- **授予和收回。** 授权页查看当前账号详情和已有授权，选范围后才加载该范围可委派的动作组与语种。角色预设只填充候选动作；同一授权按选中的一条可委派组合提交。授予失败时保留已创建的账号详情，避免重复创建。授予或收回后重读详情和授权列表。有权查看的不可收回项保留但禁用移除。授权冲突时刷新账号和可委派范围，放弃已不再可委派的选项。首批角色页不提供角色编辑，人员页只交付新建、配置、停用和授权收回。
- **依赖。** `GET /api/accounts`、`GET /api/accounts/{id}`、`GET /api/accounts/{id}/scoped-grants`、`GET /api/languages`（`primary`、`editable`）、`GET /api/roles`、`GET /api/authorization-scopes`。授予调用 `POST /api/scoped-grants`，收回调用 `DELETE /api/scoped-grants/{id}`。各按钮以对应账号或授权的许可字段驱动。

## 04 地理、地点和字典页面

### 04.1 UI-03 国家与行政区

- **结构。** 左侧懒加载行政树，右侧当前层级列表和编辑抽屉。国家页筛 `type=country`，详情按「身份」「国家配置」「名称与校对」排列。下级区域详情按「归属与来源」「几何」「名称与校对」排列。省份与城市入口在当前国家配置存在对应层级时预筛 `province` 或 `city`，仍可选择其它合法层级。
- **国家配置。** 新建国家后，在「国家配置」维护层级、邮编规则、官方语种和各自来源。普通保存后重读国家草稿。获准核验者用最新 `draftRevision` 执行通过或驳回。首次核验前显示待核，禁用新建子区；现有版本与配置草稿并列显示。核验通过后重读配置，按允许层级启用子区录入。无子层级时仍可按权限录入国家直挂地点。驳回或冲突时重读并继续展示已核验版。 [国家配置样例](contracts/v1/country-configuration.schema.json)
- **行政区操作。** 展开节点只加载对应子项，区级账号从获准根进入。新增行政区从已核验配置选允许层级和父节点。已有对象变更归属时，以最新共享修订单独提交归属字段。维护编码、几何或地点邮编用普通保存。草稿归属变化后分别重查草稿和现行路径。已发布节点待审时在原树枝保留对象入口，审批生效后刷新至新归属。未发布对象按保存结果刷新。 [普通与迁移 PATCH 样例](contracts/v1/relocation.schema.json)
- **依赖。** `GET /api/geographic-nodes`、`GET /api/geographic-nodes/{id}/configuration`、`POST /api/areas/{id}/configuration-reviews`、`GET /api/geometries`、`GET /api/geometries/{id}`、`POST /api/geometries`、`POST /api/areas`、`PATCH /api/areas/{id}`、通用草稿与翻译接口。

### 04.2 UI-04 地点、机构、来源与导入

- **结构。** 地点标签按馆区、入口、馆内点位与交通站点筛选，表格显示名称、类型、归属和核验状态。抽屉按「共享事实」「关联与来源」「逐语种」排列。机构页维护身份、范围、来源及名称。来源页维护发布方、链接、采录日期和适用范围。
- **建立关联。** 馆区先选行政区和机构，再添加服务入口。入口先选物理馆区，其他馆区在保存后可选择它作共用入口。交通站点选行政区，馆内点位选物理馆区。选择器支持按类型、范围和关键词筛选，已选项以稳定 ID 或归已核验的确切版本为准。抽屉创建与引用选择是独立操作，缺选项时导航去维护，回来重取候选。
- **来源与导入。** 选来源和作用域，再上传文件 → 建预览批次 → 检查新增、更新、冲突 → 对每条冲突选择「采用候选」或「暂存」→ 应用 → 显示对账及未解决项。应用使用当前预览修订及幂等键。`409` 时在原批次生成新预览并重做已变化的选择；文件失败保留已经选择的来源和作用域。
- **依赖。** `GET /api/places`、`GET /api/organizations`、对应 `POST`／`PATCH`、`GET /api/source-records` 及来源写接口、地理和几何读取、草稿与翻译接口。导入依次使用 `POST /api/files`、`GET`／`POST /api/import-batches`、`GET /api/import-batches/{id}`、`POST /api/import-batches/{id}/applications`。冲突后用 `POST /api/import-batches/{id}/previews` 生成新预览。坐标、邮编和来源映射以字段规格为准。

### 04.3 UI-05 标准和语言目录

- **结构。** 标准页有「字典」「地区适用规则」两个标签。字典按标准组筛选并维护共享数值、来源和名称。规则按辖区与规则组分别展示 `draft` 和 `effective`。当前来源、采用版本、继承与待复核状态直接取 `effective`。仅有继承结果且无本地草稿时继续显示生效行。语言目录只读展示语言编码及两种可用性。 [地区规则列表和详情](contracts/v1/resolved-rules.schema.json)
- **操作。** 在字典中维护一次供电或插座记录，核验后从地区适用规则选择。选规则组后清除不适用的旧候选，先确定辖区、状态和来源，再保存。明确不适用需记录依据。恢复继承保存为规则草稿，经辖区发布生效。规则页的去发布入口使用 `targetId=scopeId`。两个辖区可引用同一规格，各自显示生效状态和来源。
- **依赖。** `GET /api/dictionary-items`、`GET /api/standard-applicability-rules` 及对应写接口、`GET /api/languages`、`POST /api/catalog-reviews` 和通用草稿、翻译读取。语言目录分别读取 `primary` 和 `editable` 的完整分页结果，以编码合并展示。

### 04.4 共用表单与选择器

标识、坐标、邮编、日期和引用各在共享区出现一次，名称、简介、指引等按语言区出现。正式名称、地址或标牌原文放在共享区的「现场原文」，选出处，优先复用已核验名称。选项显示名称或编码，不接受以手输文本替代对象引用。编辑时使用草稿中随附的关联显示信息。若某字段包含无权查看的关联，该字段只读，保存时省略。读不到已选关联的名称时显示有限状态。

新建成功以回执 ID 进入详情，再获取 `allowedActions` 与 `localeActions`；没有取得新版响应之前，才刚保存的对象不进入可引用列表。基础资料核验仅对获得 `catalog.review` 的对象显示，结果以服务回执及选择器刷新为准。对组合字段的必填、空值和坐标范围，前端可用字段规格做即时校验，后端 `422` 仍按第 02.2 节显示。

## 05 内容编辑与翻译校对

### 05.1 UI-06 资料工作区

- **结构。** 列表按所属地点和资料类型筛选。详情顶部呈现编号、归属和修订，下面有「共享事实」「逐语种」「校对记录」与所属馆区入口。共享区维护来源、关联和素材。语言区按类型呈现标题、简介、正文或步骤。素材在共享区选择，替代文本从有权限的素材记录维护入口打开。
- **创建。** 选类型、归属、原文语种和来源 → `POST /api/content-records` → 打开返回 ID 的草稿 → 填写原文并保存。原文尚未保存时，其他获准语种可打开、查看缺译并保留未提交输入，提交区说明需先保存原文。地点层级及资料关联按第 04.4 节，保存共享事实调用 `PATCH /api/content-records/{id}`。
- **正文与步骤。** 文本和选择引用顺序可调。切换编辑语种时通过 `GET /api/records/{id}/reference-labels?locale={locale}` 获取当前关系标签。只有响应的记录、语种及 `draftRevision` 与当前编辑器一致时才消费，修订不同先重取草稿。缺译只显示获准编码，越权关系没有链接或标识。新关系先保存再供正文引用。前端提交字段定义中的片段和 ID。 [逐语种引用样例](contracts/v1/reference-labels.schema.json)
- **素材。** 从 `GET /api/media-assets` 选择可引用版本。需要新图时，用 `POST /api/files` 登记文件，再创建素材和逐语种替代文本，经目录核验后回资料页选择。上传完成显示登记回执，登记并核验后才进入可引用列表。资料内的媒体用受控预览接口读取。

### 05.2 逐语种保存与校对时序

| 起始状态 | 操作者动作与请求 | 成功后的页面结果 |
| --- | --- | --- |
| 已建立记录，无当前语种译文 | 按对象许可显示新增译文；用 `PATCH /api/records/{id}/translations/{locale}` 提交预期原文修订及译文修订 `0`。 | 重读草稿，当前语种更新修订和状态，其余尚未提交的面板输入保留。 |
| 译文存在，或切换阅读面板 | 进入时从已读草稿取授权内容，以对应 `localeActions` 启用编辑。每个语种生成独立保存请求。 | 保存完成后刷新当前事实。切换语言时页面主语言不变。 |
| 原文改变 | 保存原文，重新读取草稿及校对摘要。 | 既有译文保留，需复核的状态由接口返回。其他未提交译文使用原修订保留，保存时先展示原文变化并要求重新核对。 |
| 具备具体语种校对权限 | 打开该语种校对记录，检查所选原文与译文修订，选择通过或退回并填写意见。提交同路径的 `POST .../reviews`。 | 重读草稿与 `GET .../reviews`，显示绑定修订的决定。并发冲突保留获准输入，重新比对后再发。 |
| 内容已核验 | 从内容详情打开所属馆区，在馆区共享区选择该确切版本并保存 `contentRefs`，再以馆区 ID 进入发布工作区。 | 独立内容保留目录版本。馆区候选显示所选内容版本，旧生效版仍使用原引用。 |

内容页读取 `GET /api/content-records`、`GET /api/records/{id}/draft`、逐语种校对历史及已配置选择器。不同语种可由不同人独立保存。导航到他人授权已收回的旧语言地址时，删除无权的 `locale` 参数并选首个仍可见面板，若无则停在共享区。

### 06.2 操作与回执

| 操作 | 确认前必须读取 | 提交和界面结果 |
| --- | --- | --- |
| 提交发布 | 以最新 `draftRevision` 获取 `operation=publish` 的 `publication-options`，展示候选、语言移除及阻塞。勾选项改动后重取预检。 | `canSubmit` 为真且已完成所需确认时，提交 `POST /api/publication-requests`。打开返回的待审申请，当前生效保持既有指针。 |
| 审核通过或驳回 | 申请详情、冻结预览及申请记录的预期公开条件。根据申请的 `allowedActions` 提供操作。 | `POST /api/publication-requests/{id}/decisions`。批准将移除语种的申请须明确确认，发送 `acknowledgeLocaleRemovals:true`。批准后重读生效预览，驳回后重读草稿与申请。`201 conflicted` 与普通 `409` 按各自状态处理。 |
| 取消发布 | 当前生效版、`visibilityRevision` 和 `operation=withdraw` 的影响报告。若有阻断依赖，展示授权清单或范围内提示。 | 影响检查无阻塞后提交撤下申请，仍走审核。申请成功只能显示待审撤下，审批完成后生效预览才关闭。 |
| 紧急暂停 | 当前公开状态和 `operation=pause` 的影响报告。确认对话框要求理由、选择来源。 | `POST /api/publication-restrictions` 发送 `pause`，以回执刷新状态与管理预览。 |
| 撤销确切版本 | 版本详情及 `operation=revoke-version` 的影响报告，可从历史确切版本发起。 | 使用 `POST /api/publication-restrictions` 提交 `revoke-version`、`versionId`、理由及来源。成功后刷新被处理版本和当前状态。 |
| 恢复 | 从历史页面选来源版本，以当前 `pauseEventId` 读 `operation=restore` 的候选。显示实际将恢复的字段和可能移除的语种。 | 提交 `restore`、历史版本与暂停事件，等待审核。原暂停仍有效；新暂停出现时显示冲突和重读后的当前状态。 |
| 导出 | 当前授权生效状态和所选语种，确认当前目标。 | `POST /api/exports` 创建导出，按回执 ID 取状态或下载。`403`／`404` 取消下载并清除失效链接。 |

写入的请求条件取自最近一次功能读取。普通提交和恢复经过明确预检与确认，需要确认扩展语种移除时才回传预检的 `localeRemovalAcknowledgement`。审核提交按申请中记录的条件走审核接口。影响清单只显示获准详情，依赖阻断及不可见的语言变化用汇总状态呈现。特殊动作的网络超时处理按第 02.2 节。

影响清单按接口返回的 `relationshipType` 与 `effect` 展示逐项结果。普通撤下受阻时禁止提交。紧急暂停和确切版本撤销显示所选对象或版本及影响，再由服务端按第 08.2.1 节规则执行。结果成功后重新读取影响对象和当前生效状态。 [引用规则](全球旅游后台首版实施方案.md#0821-引用关系与公开结果) · [影响和限制样例](contracts/v1/publication-dependencies.schema.json)

### 06.3 UI-08 覆盖检查与场景

- **结构。** 「检查」显示出发市场、目的地、语言、场景和可选适用条件；结果区按步骤列状态、原因、可访问资料和走查操作。「场景」为模板列表和编辑抽屉，步骤支持排序，逐行设置编码、必备标志、资料类型和匹配条件。
- **检查。** 选择市场后读该国核验配置取语言。目的地、证件签发地、途经辖区用授权树选择。旅行目的从字典选择，日期用日期控件。场景和全部必选参数齐备即允许检查，其他条件可空。由 `GET /api/coverage-checks` 返回已核验、缺译、缺资料、待复核或不适用及原因。更改条件使旧结果失效，重新执行检查。
- **走查。** 对本次组合获 `coverage.review` 后可通过或退回；提交 `POST /api/coverage-reviews`，附原检查条件、`expectedCoverageRevision` 与理由。成功后重新检查。`409` 提示依赖已变化，新结果复核前保留旧理由但禁用直接重提。
- **场景维护。** `GET /api/coverage-scenarios`、`GET /api/coverage-scenarios/{id}` 读取，在 `coverage.manage` 授权范围内创建或编辑步骤，使用该场景修订提交。条件用相应 ID、字典编码、日期或简单多选构成。编辑后回到原筛选列表，覆盖检查重新取模板。覆盖状态全由服务响应决定。
