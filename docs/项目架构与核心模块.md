# 项目架构与核心模块

本文档记录 Codex 对 `finger-more-admin` 当前项目结构、核心模块和约定的理解，用于后续更准确、快速地定位问题。后续涉及架构、路由、权限、接口、地理数据、发布中心等调整时，应同步更新本文档。

## 项目定位

`finger-more-admin` 是一个面向 `finger-more` 业务的后台管理系统，当前核心能力围绕：

- 多语言后台界面与多语言业务数据展示
- 账号、角色、权限管理
- 国家、省份、城市、点位、地标等基础数据管理
- 地理信息录入、检查与地图展示
- 面向跨国旅行的信息中心资料维护，例如服务平台、交通、服务、注意事项、文化、支付与货币
- 发布中心中的多层级数据发布流程

## 技术栈

- 构建工具：Vite
- 前端框架：React 19
- 类型系统：TypeScript
- UI 组件库：Ant Design
- 路由：react-router-dom
- 全局状态：zustand
- HTTP 客户端：axios
- 自动导入：unplugin-auto-import

项目约定见 `.agents/skills/react-dev/SKILL.md`。开发时优先遵循该文件中的目录、接口、状态、组件和自动导入规则。

## 目录职责

```text
src/
  api/          接口层。已有 axios request 封装，但多数业务接口当前仍使用 mock 数据。
  assets/       静态资源。
  components/   跨页面复用组件，例如 GeoMap、LanguageLabel、LanguageText。
  context/      React Context，目前主要是全局语言列表。
  db/           静态业务数据与大体量地理数据。
  i18n/         Ant Design locale 映射。
  layouts/      后台主布局，包含侧边栏、顶部栏、菜单权限和语言切换。
  mock/         模拟数据和内存态模拟后端。
  pages/        页面模块，每个页面一个目录，入口为 index.tsx。
  router/       路由配置与登录保护。
  store/        zustand store，目前核心是 useAuthStore。
  types/        跨模块业务类型。
```

## 应用启动与全局装配

入口文件 `src/main.tsx` 只负责挂载 `App`。

`src/App.tsx` 是全局装配层，主要职责：

- 根据当前语言配置 Ant Design `ConfigProvider` 的 locale，并通过 `theme.components` 统一 `Input`、`InputNumber`、`Select` 控件字号为项目内已使用的 `12`；`Select` 同时配置选择框正文 `fontSize` 与下拉选项 `optionFontSize`，弹窗内选择框正文与 option 字号保持一致
- 项目弹窗统一使用 `src/components/DraggableModal`，内部基于 Ant Design `Modal` 固定 `mask={false}`、`closable={false}`，并通过 `modalRender` 支持从弹窗头部拖拽移动；弹窗标题统一为 `18px` 字号，标题、弹窗内主按钮、`Form.Item` 标题短竖线、输入框/数字输入/下拉框 hover 与 focus 边框、Slider 激活色、Radio/Checkbox hover 与 checked 激活色优先使用 `themeColor` 入参，未传时默认蓝色 `#1677ff`；footer 按钮文案统一使用 `LanguageLabel`，组件默认用 `confirm`、`cancel` 渲染确定/取消；弹窗内 `Form.Item` 标题前统一展示 4px 宽、12px 高的主题色短竖线，竖线与标题文字保持 10px 间距；弹窗内容子树中继续打开 `DraggableModal` 时会继承当前主题色，兄弟节点方式渲染的二级弹窗需显式传递相同 `themeColor`
- 通用数据项录入使用 `src/components/DataFormItem`，组件以 `{ type, content }` 返回数据类型和内容；类型支持文本、标签、文件，默认可选类型为文本和标签；文本类型使用单输入框，标签类型使用组件内置的多语言输入行逻辑，文件类型使用 `Upload` 上传控件；当入参 `type` 只传入一项时不展示 Radio，直接展示对应的数据采集模块，并通过内部同步写入类型值，避免额外渲染隐藏表单项和外层布局容器；新增多语言标签录入统一使用 `DataFormItem type={['label']}`
- 约束弹窗内按钮、下拉、输入框、表格统一使用小一号尺寸：弹窗表单通过 `<Form size="small">` 下发输入类小尺寸，弹窗内 `Select`、`Input`、`InputNumber`、自定义 `Button`、`Table` 显式设置 `size="small"`，Modal 默认 footer 按钮通过 `okButtonProps` 和 `cancelButtonProps` 配置小尺寸；弹窗内 `Form.Item` 间距通过全局样式覆盖为 `14px`，比 Ant Design 默认 `24px` 缩小 `10px`；非弹窗场景使用 Ant Design 默认尺寸
- 挂载 `GlobalLanguageProvider`
- 挂载 `RouterProvider`
- 如果本地已有登录用户，启动时调用 `getCurrentUser` 刷新用户信息
- 刷新用户失败时执行登出

全局语言和登录态都来自 `useAuthStore`。

## 路由结构

路由集中在 `src/router/index.tsx`。

- `/login`：登录页，独立于后台布局。
- `/`：受 `RequireAuth` 保护，内部使用 `BasicLayout`。
- `/dashboard`：首页。
- `/publish-center`：发布中心，当前通过 `React.lazy + Suspense` 做路由级懒加载，避免初始进入后台时同步加载发布中心和大体量地图相关逻辑。
- `/info-center/*`：信息中心。
- `/master-data/*`：基础数据。
- `/system/*`：系统管理。
- `*`：404 页面。

当前 `RequireAuth` 只校验是否存在 token。菜单层有权限控制，但路由层没有按权限 code 做二次拦截；如果后续要强化安全边界，应在路由或页面入口增加权限校验。

主布局在 `src/layouts/BasicLayout.tsx`。

核心职责：

- 侧栏菜单顺序当前为：首页、发布中心、基础数据、信息中心、系统管理

## 认证、用户与语言状态

认证状态在 `src/store/useAuthStore.ts`。

状态字段：

- `token`
- `user`
- `currentLanguage`

核心方法：

- `login(token, user)`：写入 token、用户信息、默认语言到 localStorage 和 store。
- `logout()`：清理 localStorage 和 store。
- `hasPermission(code)`：判断当前用户是否拥有权限。
- `setCurrentLanguage(language)`：只允许切换到当前用户拥有的语言。
- `setUser(user)`：刷新用户信息，并保证当前语言仍然可用。

当前状态持久化直接使用 localStorage，没有使用 zustand persist 中间件。

## 接口层与 mock 数据

`src/api/request.ts` 已经封装 axios：

- `baseURL` 来自 `VITE_API_BASE_URL`，默认 `/api`
- 请求自动注入 `Authorization: Bearer <token>`
- 响应直接返回 `response.data`
- 401 时自动登出

但当前多数业务接口仍直接操作 `src/mock/db.ts` 或其他静态数据，属于 mock 后端阶段。后续接真实后端时，推荐保持组件只调用 `src/api/*` 函数，在 API 文件内部逐步从 mock 迁移到 `request`。

## 多语言体系

项目有两类多语言：

1. UI 文案多语言
   - 集中在 `src/components/LanguageLabel/LabelMap.ts`
   - 通过 `LanguageLabel` 渲染固定界面文案
   - 通过 `getLabel` 获取字符串
   - `LanguageLabel` 的英文副文案继承父级 `color`，只通过透明度区分层级，保证父级设置高亮色、选中色时主副文案颜色一致生效
   - `LanguageLabel` 支持 `direction` 参数控制双语排列方向：`row` 为水平排列且上下居中，`col` 为上下排列且左右居中，默认保持 `row`

2. 业务数据多语言
   - 国家、省份、城市、点位、地标等数据自身携带多语言字段
   - 通过 `LanguageText` 按当前语言展示
   - `LanguageText` 的英文副文案继承父级 `color`，只通过透明度区分层级，保证父级设置高亮色、选中色时主副文案颜色一致生效
   - `Select.options` 展示多语言业务数据时，`label` 统一使用 `LanguageText` 组件，展示规则对齐顶部语言选择：当前语言为非英文时展示当前语言主文案和英文副文案，英文时只展示英文主文案，避免在 options 中提前取 `map[language]` 字符串
   - 筛选类单选 `Select` 如果下拉面板需要双语展示，但选择框内不需要双语节点，option 额外提供纯文本字段，并通过 `optionLabelProp` 指向该字段，让已选值展示纯文本

当前语言由 `useAuthStore.currentLanguage` 决定。用户可切换语言受当前账号 `languages` 限制。

## 界面文案约定

创建类按钮和创建态标题统一展示为“新建”，不在“新建”后拼接具体业务对象名，例如不使用“新建国家”“新建类型”。

## DOM 层级约定

组件结构应减少不必要的真实 DOM 包裹和无效节点。单子节点且没有布局、滚动、定位、对齐、表单绑定或语义容器需求时，直接返回子节点；多子节点优先使用 `Fragment`；只有在确实需要间距、滚动区域、拖拽范围、表单绑定、视觉分组或语义结构时才使用 `div`、`Space`、`Card` 等真实容器。

覆盖场景包括：单按钮/单输入工具栏不使用 `Space` 只承载 `marginBottom`，可将间距下沉到控件自身；单子节点 `Fragment`、只包一层样式且样式可下沉的 `div`、无实际语义的嵌套 `Card`、固定值隐藏控件、无内容占位节点都应优先移除或合并。

保留场景包括：承载滚动区域、flex/grid 布局、拖拽范围、绝对定位上下文、事件委托、语义分组、可访问性角色、表单字段绑定、列表 key 边界、Ant Design 组件要求的 wrapper。后续开发或巡检时，如果发现可减少 DOM 层级且能保证交互逻辑、表单数据结构和视觉布局不变，应直接同步优化；无法确认影响时保留现状并记录原因。

表单封装组件不应为了固定类型或固定状态额外渲染隐藏控件；可由组件内部同步到表单值的状态，应避免隐藏 `Form.Item` 和隐藏 `Input`。`Form.Item noStyle` 只用于给自定义控件绑定表单值，不作为布局容器。

## 表格展示约定

后台列表页默认使用 Ant Design `Table`。当列较多或内容较宽时，横向溢出应由表格主体滚动处理，优先配置 `scroll={{ x: 'max-content' }}` 或明确的 `scroll.x`。

表格存在操作列时，操作列应固定在右侧，并设置稳定列宽，保证用户横向滚动查看主体数据时仍能直接操作当前行。普通数据列也应设置合理列宽，表头使用不换行展示，确保标题保持一行，不通过换行撑高表格。

表格单元格内容为空时统一展示 `-` 占位，优先使用 `src/utils/table.tsx` 中的 `renderTableEmptyPlaceholder` 处理，不直接返回 `null`、空字符串或空白内容。

### 系统管理

- `src/pages/System/Role/index.tsx`
- `src/api/adminUser.ts`

### 基础数据

位置：

- `src/pages/MasterData/*`
- `src/db/countries.ts`
- `src/db/provinces.ts`
- `src/mock/cities.ts`
- `src/mock/db.ts`
- `src/types/destination.ts`
- `src/types/point.ts`

职责：

- 国家、省份、城市管理
- 国家、省份、城市管理页均展示 `可见倍率`，默认 `8x`，当前在页面内通过表格单元格原位编辑维护
- 国家管理页列表中 `国家代码/国家名称` 表头简化为 `编码/名称`；名称单元格使用高亮色展示并支持点击打开国家信息详情/绑定弹窗。国家管理页保留 `信息绑定` 操作，可在弹窗内修改可见倍率，并为国家绑定国标、语言、货币、时区、气候、入境信息、注意事项、安全和文化；信息绑定弹窗为五列布局，第一列和第二列在基础等宽列宽上各收窄 `80px`，第一列二级标题为 `基本信息`，包含国家编码、名称、语言、货币、时区、气候和可见倍率，其中可见倍率固定为基本信息最后一项，时区来自 `TIMEZONE_INFOS`，气候来自 `CLIMATE_INFOS`；第二列二级标题为 `国标`，按 `STANDARD_SPEC_INFOS` 中的国标类型动态生成标准绑定项，每一项标题为国标类型名称，下拉选项为对应国标的 `parameter` 标准列值；第三列二级标题为 `入境信息`，承载入境政策、海关禁限、通讯、网络、支付、交通规则、驾照，其中入境政策来自 `ENTRY_POLICY_INFOS`，海关禁限来自 `CUSTOMS_RESTRICTION_INFOS`，通讯来自 `COMMUNICATION_INFOS`，网络来自 `NETWORK_INFOS`，支付来自 `PAYMENT_METHOD_INFOS` 并支持多选，交通规则来自 `TRAFFIC_RULE_INFOS` 并使用一行排列的 Radio 维护通行方向，驾照来自 `DRIVING_LICENSE_INFOS`；第四列二级标题为 `文化`，参考国标内容逻辑按 `CULTURE_INFOS` 中的文化类型动态生成绑定项，每一项标题为文化类型名称，下拉选项为该类型下的具体文化项目并支持多选，表单值保存到 `cultureInfoIds[typeKey]`，小费文化作为习俗类型下的一条具体项目维护；第五列包含 `注意事项` 和 `安全` 两个独立二级标题，注意事项来自 `SECURITY_RISK_INFOS`，安全包含食品、水、治安 3 个维度，均使用 0-100、步长 1 的滑动输入条，并以危险、注意、极度安全三个梯度纵向双语标注，Slider 宽度比容器收窄 `60px` 并左右居中，标记主文案字号为 `10px`；国标/货币/时区/气候/入境信息/注意事项/文化/支付选项来自 `src/mock/information.ts` 中的信息中心 mock 列表，语言选项来自信息中心语言数据；信息中心交通列表模块仍独立维护，国家绑定内仅维护交通规则与驾照要求
- 点位与地标管理
- 点位类型维护归属点位管理页，通过页内“类型列表”弹窗管理；地标类型维护归属地标管理页，通过页内“类型列表”弹窗管理；类型列表参考国标类型结构，列统一为 `code / name / value`，code 为类型记录业务编码，点位类型使用 `POINT_TYPE_随机11位数字`，地标类型使用 `LANDMARK_TYPE_随机11位数字`，name 为多语言类型名称，value 为点位/地标记录实际保存和匹配的业务类型值
- 点位支持不同类型的扩展字段，例如景点、住宿、交通、美食、购物等

其中部分页面直接读取 `src/db/*` 静态数据，部分页面通过 `src/api/*` mock CRUD 操作。

### 信息中心

位置：

- `src/pages/InfoCenter/Traffic/index.tsx`
- `src/pages/InfoCenter/Communication/index.tsx`
- `src/pages/InfoCenter/Language/index.tsx`
- `src/pages/InfoCenter/Payment/index.tsx`
- `src/pages/InfoCenter/Payment/CurrencyListModal.tsx`
- `src/pages/InfoCenter/StandardSpec/index.tsx`
- `src/pages/InfoCenter/ServiceInfo/index.tsx`
- `src/pages/InfoCenter/SecurityRisk/index.tsx`
- `src/pages/InfoCenter/CultureCustoms/index.tsx`
- `src/pages/InfoCenter/CultureCustoms/TypeListModal.tsx`
- `src/mock/information.ts`

职责：

- 语言维护使用 `GLOBAL_LANGUAGES` 数据，当前作为信息中心第一项，对外路由为 `/info-center/languages`；语言数据的 `code` 是业务编码，统一使用 `LANGUAGE_随机11位数字`，真实语种 key 保存在 `localeCode`；列表列统一为 `code / 名称 / value / 补充`，其中 value 展示国际通用语言标识 `localeCode`，补充暂无数据并按表格空值规范显示 `-`
- 货币不再作为信息中心独立模块注册菜单、页面和权限入口；旧 `/info-center/currencies` 路由仅保留跳转到 `/info-center/payment`。货币基础数据继续使用 `CURRENCY_INFOS`，在支付模块内通过“货币列表”弹窗展示，并作为国家信息绑定弹窗中“货币”项的数据来源；货币数据的 `code` 统一使用 `CURRENCY_随机11位数字`，value 使用 ISO 4217 三字母币种标识

GEO_TREE

`GeoNode` 包含：

- `code`
- `name`
- `geo`
- `children`

`geo` 是 MultiPolygon Feature，并带有面积质心 `centroid`。质心计算逻辑在 `src/db/geo/types.ts`，用于地图标签和选中聚焦。

当前目标层级是 `洲 / 国家 / 省级行政区 / 市县区等末级行政区`。实际数据中，除 `CN` 外目前 `AD / AM / AZ / GB / LI / LV / MD / ME / MK / MT / SI / SM / UG / US` 已维护到第四层；`GB` 已重组为 `GB -> GB-ENG/GB-NIR/GB-SCT/GB-WLS -> 地方行政区`，`AD / AM / AZ / LI / LV / MD / ME / MK / MT / SI / SM / UG` 按数据来源待考证兜底规则新增 `国家编码-00` 伪一级并将旧节点迁入其下，其中 `AZ-00` 下继续保留 `AZ-NX -> AZ-BAB/AZ-CUL/...` 的既有子级关系。目录维护方式应对齐 `AS/CN`：父级目录保留 `index.ts`，其下一级数据放在当前目录的独立 `.ts` 文件中；待考证但需要先统一四层结构的国家可新增 `国家编码-00` 伪一级，名称为 `*+国家名称`，geo 数据复用国家数据。按“实际二级行政区误挂国家一级”的口径，后续优先复核 `BA`，并条件复核 `PH / RS`。名称中包含“市/县/郡/自治市”不等于层级错误，详见 `docs/geo数据层级检查.md`。

### GeoMap 组件

位置：`src/components/GeoMap/index.tsx`

`GeoMap` 是 Canvas 自绘地图组件，不依赖第三方地图 SDK。

输入能力：

- `continentRegions`
- `regions`
- `provinceRegions`
- `cityRegions`
- `publishedCodes`
- `activeCodes`
- `marker`
- `focus`
- `langKey`
- `width`：可选固定逻辑宽度；不传时根据外层容器宽度自适应
- `height`
- `style`
- `zoomThresholds`

交互能力：

- 鼠标滚轮缩放
- 鼠标拖拽平移
- 外部传入 focus 后自动定位和缩放
- 重置地图视图

性能策略：

- 对传入区域预处理 polygon rings、区域 bounds 和标签中心，缩放/拖拽重绘时直接复用预处理结果
- 视口 bounds 基于预处理后的区域 bounds 合并，避免每次绘制重新遍历完整坐标集合
- 鼠标滚轮缩放会累积 wheel delta，并通过 `requestAnimationFrame` 合帧更新 zoom，避免高频 wheel 事件连续触发 `setZoom`
- Canvas DOM 物理像素按 `devicePixelRatio` 放大，绘图坐标仍使用逻辑像素，通过 `ctx.setTransform` 保持高清显示和原有坐标计算
- 未传 `width` 时通过 `ResizeObserver` 跟随外层容器宽度自适应，发布中心不再传固定 `1040px` 地图宽度

显示策略：

- 按 zoom 阈值在大洲、国家、省份、城市层级之间切换
- 当前同一时间只渲染一个主层级
- 放大到省份/城市层级时，国家边界作为底图保留
- `activeCodes` 可传入从父到子的选中路径，但 `GeoMap` 只会倒序取最后一个能匹配到 geo 的编码作为唯一选中态，避免选中子级时父级仍显示 active 样式
- 发布态、选中态通过边框颜色区别
- 选中态区域在普通图层后补绘顶层高亮轮廓；选中点位/地标标记和选中区域名称也置顶绘制，避免被其它 Canvas 内容遮挡
- Polygon 绘制时将外环和内环放入同一个 path，并使用 `evenodd` 填充规则正确扣出湖泊等内环洞
- 目前城市边界渲染被 `CITY_BOUNDARIES_ENABLED = false` 关闭，因为城市级 geo 数据尚不完整

后续待优化项：

- 更细粒度拆分地理数据：当前 `/publish-center` 和 `GEO_TREE` 已改为懒加载，但进入发布中心后仍会一次性加载完整地理树；后续可按大洲、国家、层级或当前选中区域继续动态加载，尤其避免在城市边界关闭时提前整理所有城市 region。
- 绘制前做视口裁剪：当前当前层级的 region 会整体进入绘制流程；后续可基于预处理 `bounds` 先过滤不在视口内的区域，减少拖拽和高 zoom 下的无效 path 绘制。
- 标签密度与碰撞控制：当前会绘制当前层级全部区域标签；后续可做屏幕范围过滤、按面积/重要性抽样、文字 bbox 碰撞避让，避免标签过密和无效 `measureText`。
- 发布中心传参稳定化：`mapRegions`、`activeCodes` 等数组当前在页面 render 中重新创建，容易触发 `GeoMap` 预处理和重绘；后续可用 `useMemo` 固化派生结果，只在选中项或地理数据变化时更新。
- 静态图层缓存：国家/省份边界大多是静态数据，后续可按层级缓存到离屏 canvas 或 `Path2D`，交互时只重绘动态高亮、标签、marker。
- 大数据绘制线程隔离：如果后续城市级数据完整开放后仍卡顿，可评估 `OffscreenCanvas` 或 Web Worker，把重几何绘制从主线程拆出去。
- 交互事件统一：当前主要支持 mouse wheel 和 mouse drag；后续可统一到 pointer events，并补触控拖拽、触控板缩放惯性等交互兼容。
- 样式和绘制依赖收敛：`oceanStyle`、层级样式等对象仍在组件 render 中合并；后续可用 `useMemo` 收敛引用变化，减少与地图无关的父组件 render 触发重绘。

### 发布中心

位置：

- `src/pages/PublishCenter/index.tsx`
- `src/api/publish.ts`
- `src/mock/publishStatus.ts`

发布中心是当前最复杂的聚合页面，连接了：

- 国家、省份、城市静态数据
- 点位、地标 mock 数据
- `GEO_TREE` 地理树，页面挂载后通过动态 `import('@/db/geo')` 加载，避免跟随主入口或路由入口同步加载
- `GeoMap` 地图组件
- 发布状态内存 Map
- 多语言展示

主要逻辑：

- 将动态加载后的 `GEO_TREE` 拆成大洲、国家、省份、城市 region 列表
- 将 `COUNTRIES / PROVINCES / CONTINENTS` 的多语言名称补入 geo properties
- 提供国家、省份、城市、点位、地标五级级联筛选
- 选中区域或点位后计算地图 focus
- 根据发布状态展示发布、取消发布、审批中状态
- 主体布局分为两列：左列固定 `1000px`，承载自适应剩余高度的地图和固定 `420px` 的五级列表；右列撑满剩余页面空间并承载发布操作

当前发布状态存储在内存 `Map` 中，刷新页面会丢失。

## 当前架构观察

优点：

- 目录分层清晰，模块边界基本明确
- 路由、布局、权限、语言状态集中管理
