# Geo 数据层级检查

检查日期：2026-06-23

检查范围：`src/db/geo`

目标层级：

```text
洲
  国家
    省/州/省级行政区
      市/县/区/郡等末级行政区
```

本次以 `AS/CN` 的维护方式为参考：`CN` 下是省级节点，例如 `CN-11`；省级节点下再维护市县区节点，例如 `CN-11-0101`。

本轮口径修正：本报告要排查的是“实际属于国家下二级行政地区，却维护在国家直下一级”的数据，不再把中文名称中带 `市 / 县 / 郡 / 自治市 / 镇` 的节点直接判定为错误。很多国家的一级行政区本来就叫“县、郡、自治市、广域市、城市州”等。

## 口径修正后的结论

- 当前全量树包含 6 个洲、193 个国家、4063 个国家直下子级节点、3850 个第四层节点。
- 除 `CN` 外，`GB` 和 `US` 已具备第四层结构：`GB -> GB-构成国 -> 地方行政区`，`US -> US-州 -> US-州-县`。
- 除 `CN` 外，没有发现“同一个国家直下同时存在带子级的省节点和无子级的市县节点”的硬性结构混层。
- 按“真实行政层级误挂”口径，`GB` 已处理；剩余优先看 `BA`，再条件复核 `PH`、`RS`。
- `JP / KR / VN / RO / IE / HR / EE / LV / SI / MW / CV / TL / BN / NO / TT` 等国家虽然名称命中“县、郡、市、自治市”，但更可能是一级行政区或省级等价单位，不应自动下沉。
- `BD / CZ / NP / AE / MY` 更偏向翻译、数据版本或非行政边界问题，和“二级行政区误挂一级”不是同一类问题。

## 实际二级误挂一级候选

| 级别 | 国家 | 当前国家直下维护 | 判断 | 示例 | 建议 |
| --- | --- | --- | --- | --- | --- |
| 高风险 | `BA` 波斯尼亚和黑塞哥维那 | `BA` 下同时有州、特区，以及 `BA-X..~` 这类城市/区域节点 | 波黑行政体系包含实体、布尔奇科特区、州/市镇等层级；当前 `BA` 直下混有不同层级节点，疑似缺少实体父层 | `BA-BIH 黑塞哥维那-涅雷特瓦州`、`BA-BRC 布尔奇科特区`、`BA-X07~ 特雷比涅`、`BA-X02~ 巴尼亚卢卡` | 人工确认后重组为 `BA -> Federation / Republika Srpska / Brcko -> canton / municipality` 一类结构，或先在元数据中标记节点真实层级 |
| 条件复核 | `PH` 菲律宾 | 83 个省、独立城市或都会城市类节点直接挂在 `PH` 下 | 如果产品把 `Region` 作为省级父层，则当前省/独立城市属于国家下二级，确实误挂一级；如果产品把省和独立城市视为国家一级 LGU，则大部分节点可保留，但独立城市仍需明确粒度 | `PH-SLU 苏禄省`、`PH-SCO 三投斯将军市`、`PH-MNL 拉斯皮纳斯`、`PH-BCD 巴科洛德` | 先确认菲律宾是否采用 `Region -> province/independent city -> city/municipality`；若采用四层，则整国需要补 `Region` 父层 |
| 条件复核 | `RS` 塞尔维亚 | 25 个行政区/贝尔格莱德直接挂在 `RS` 下 | 当前节点主要是 administrative districts，这些更像国家行政服务分区，不是自治省/城市/市镇这类政治或地方自治层级；是否算“二级误挂”取决于产品层级口径 | `RS-01 北巴奇卡州`、`RS-06 南巴奇卡州`、`RS-00 贝尔格莱德` | 确认塞尔维亚是否要按 `autonomous province / city / municipality` 维护；若是，当前 districts 不应作为国家一级省级行政区直接使用 |

## 不是层级误挂的典型名称命中

这些国家容易被中文后缀误报，但从层级语义看不应自动移动：

| 国家 | 命中原因 | 判断 |
| --- | --- | --- |
| `JP` 日本 | 大量节点叫“县”，另有“府/都/道” | 日本都道府县是国家一级省级行政区，不能按“县”字下沉 |
| `KR` 韩国 | 首尔、广域市、特别自治市与道同层 | 这些是省级等价单位，不能按“市”字下沉 |
| `VN` 越南 | 直辖市与省同层 | 胡志明市等是省级等价单位 |
| `KH / KP` 柬埔寨、朝鲜 | 市、特别市与省/道同层 | 多数是一级等价行政区或特殊市 |
| `RO / IE / HR / EE / LT / LR / MW / TL / CV / BN / NO / TT` | 县名、郡名、自治市名较多 | 这些国家的县/郡/自治市多是国家一级行政区或一级地方单位 |
| `LV / SI / ME / MD` | 自治市、区、市镇类名称较多 | 这些国家一级行政区本身就可能是 municipality/district 类型 |

## 翻译、版本或非行政边界问题

| 国家 | 现象 | 判断 | 建议 |
| --- | --- | --- | --- |

## 后续处理建议

- `BA / PH / RS` 不建议直接批量移动，先补一份国家层级映射表，明确每个国家采用哪个行政父层。
- 给 `GeoNode` 或旁路配置增加 `geoLevel` / `adminLevel` 元数据，例如 `continent / country / province / cityCounty / nonAdmin`，避免后续继续靠中文名称判断层级。
- 翻译问题与层级问题分开处理：`BD / CZ / NP / AE / MY` 优先建“名称修正/数据版本”任务，不和层级迁移混在一起。
- 若产品层级必须统一为四层，建议逐国补父层数据；若短期只展示三级，业务文案应使用“地区/行政区”而不是固定写“省”。
