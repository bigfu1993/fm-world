| `qa-v1/catalog` | 两个测试国家和两个馆区，提供一个共用入口、两组故意冲突的坐标、一个有两个来源键的城市，以及三套中英文供电标准。标准值用测试标记，不采入真实国家资料。 |

### 03.1 首批表单和传输字段

表中名称是首批 API 及对应表单的字段键。普通关联保存稳定 ID，参与候审冻结的直接引用使用 `{id, referenceVersionId}`。多选保存有明确定义的数组。字段标记为可选时允许保存草稿并在缺失时省略公开输出。国家配置决定邮编校验，地理发布通过后才更新公开父链。

| 所属类型 | 共享字段与选择关联 | 逐语种字段 |
| --- | --- | --- |
| `country`、`administrative-area` | `code`、`areaLevel`、`parentId`（国家级为空）、`sourceIds`，可选 `geometryId`。`areaLevel` 由各国配置启用 | `name`，可选 `aliases`。 |
| 国家配置，归 `country` | `areaLevels` 指定允许的父子层级，`postalCodeRule` 定义是否必填及允许格式，`officialLocales` 选择语言代码。`configurationSources` 按以上三个键分别保存来源 ID 数组 | 无。显示名称读取已核验语言字典。 |
| `organization` | `code`、`scopeId`、`sourceIds`，可选 `websiteUrl` | `name`，可选 `aliases`、`summary`。 |
| `venue` | `code`、`areaId`、`organizationId`、`sourceIds`、`entranceIds`。可选 `contentRefs`，选择用于本馆区发布的已核验简介、展览、史料或到达指引版本。`streetNumber`、`postalCode`、`latitude`、`longitude` 按地区与使用条件可空 | `name`、`streetName`，可选 `summary`、`aliases`、`addressDetail`。`summary` 为简短摘要，馆区说明正文归 `venue-introduction`。展示地址由行政区译名、街道译名、门牌及邮编组装。正式地址原文按 `officialNames` 登记。 |
| `entrance`、`interior-point`、`transport-stop` | `code`、`sourceIds`、可选 `latitude`、`longitude`。入口及馆内点位用 `parentPlaceId`，独立交通站点用 `areaId` | `name`，可选 `summary`。 |
| 字典项 `dictionary-item` | `groupCode`、`code`、`sourceIds`。`power-supply` 组有数值字段 `voltageV`、`frequencyHz`，`power-plug` 组用项编码标识型式 | `name`，可选 `summary`。 |
| 辖区规则 `standard-rule` | `scopeId`、`groupCode`、`status`、`itemIds`、`sourceIds`，可选 `validFrom`、`validUntil`。`configured` 须有相应字典组条目，`not-applicable` 须有依据，`inherit` 由运营显式提交。失效由时间及撤下状态计算 | 可选 `instructions`，纳入发布时适用双语要求。 |
| `exhibition`、`historical-record`、`arrival-guide`、`venue-introduction` | `ownerId`、`sourceIds`，可选 `mediaRefs`、`historicalRecordRefs`。到达指引须选 `entranceId`、`transportModeId`、`stopId`。展览归实际馆区，选发入口使用 `entranceIds` | `title`、`body`，到达指引另有 `steps`。`body` 使用有序的纯文本和引用片段，`steps` 使用有序文本与引用片段组成的步骤。 |
| 来源与素材 | 来源记录持 `scopeId`、`publisher`、`url`、`retrievedAt`。素材持 `scopeId`、`fileId`、`sourceIds`、`licenseStatus`，可选 `licenseExpiresAt`。许可状态为 `unverified`、`permitted` 或 `restricted` | 素材发布须有 `altText`，首批仅支持图片，字幕、音视频随对应模板扩展。 |

正式原文保存为有序列表 `officialNames`，单项含 `kind`、`locale`、`sourceId`，另含 `value` 或 `nameRef` 二者之一。`kind` 为 `name`、`address` 或 `signage`。可复用现有正式名称时，`nameRef` 用 `{recordId, locale, field}` 指向相应名称，不重复录入。面向旅客的正文片段取 `{type: "text", text}` 或 `{type: "reference", targetId, referenceVersionId?}`。写入时验证目标已在合法关系中，渲染时按所选语种生成译名。

传输采用记录类型区分字段集合，创建体包含 `type`、适用的 `sourceLocale` 和表内其余本次需要的字段，更新通过 `fields` 提交。`PATCH /api/accounts/{id}` 及动作类接口沿用第 05 节列出的专用字段。不存在的可选字段统一省略，坐标、时间区间、引用类型和适用关系由各自模板约束。增加字段或模板先在此登记事实归属、语种策略、载荷类型、空值语义、校验和公开范围。

国家配置随国家草稿保存。`areaLevels` 是 `{code, allowedParentCodes}[]`，层级编码在同一国家内唯一。`postalCodeRule` 是 `{required, formatCode}`，`formatCode` 取 `free-text`、`six-digits` 或 `five-digits`。配置核验通过前，每项配置都须选择来源。核验和下游读取采用同一国家的配置版本。 [国家配置核验规则](全球旅游后台首版实施方案.md#022-国家配置核验) · [配置字段与样例](contracts/v1/country-configuration.schema.json)

国家编码全局唯一，下级行政区编码在该国唯一。机构按作用域及编码唯一，馆区按直属行政区及编码唯一，馆内点位按所属馆区及编码唯一。经纬度成对校验，允许范围分别为 `[-90, 90]` 和 `[-180, 180]`。同一场所来自不同外部数据源时，按第 03 节的来源映射去重。

## 04 登录、授权与内容保存

- **首管理员初始化。** M1 空账号库使用显式 `admin:bootstrap` 命令，用户名从 `FM_WORLD_ADMIN_USERNAME` 提供，密码由安全交互或部署密钥输入。一次事务创建首管理员、系统根范围授权及初始化标记。默认主语言为 `zh`，支持已启用内容语种，初始根授权可委派第 09.2 节列出的动作及这些语种。重跑返回既有结果并保留之后的变更。实际编辑、导出、校对和发布权限仍按实施方案第 04 节判定。
- **会话与代理。** 采用服务端会话和 `HttpOnly`、`SameSite=Lax` Cookie，路径为 `/api`，HTTPS 部署启用 `Secure`。`dev`、`test` 和正式环境分别使用 `fm_world_dev_session`、`fm_world_test_session` 和 `fm_world_session`，注销按同一名称和路径清除。登录校验请求来源。登录成功和查询当前会话时返回 `csrfToken`，后续已登录写请求通过 `X-CSRF-Token` 提交，与当前会话绑定。M0 将 `dev`、`test` 的 `front-end.apiBaseUrl` 设为 `/api`，启动器向 Vite 提供由所选后端地址生成的 `FM_WORLD_API_PROXY_TARGET`，转发保留 `/api` 前缀。M1 接通会话并迁移现有前端请求封装。 [现有 API 请求封装](../front-end/src/api/request.ts#L4) · [现有启动器地址选择](../scripts/run.mjs#L36) · [OWASP CSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)
- **编辑协议。** 共享更新比对自己的 `revision`。可翻译记录创建时指定 `sourceLocale`，首次填写原文前 `sourceRevision=0`，首次填写后为 `1`。逐语种保存比对 `expectedSourceRevision` 和 `expectedTranslationRevision`。译文未建立时预期译文修订号为 `0`，普通译文须基于已保存的原文。保存原文时同步推进原文修订并判定旧校对待复核。发布候选中的共享字段、归属、引用、译文或校对变化在同一事务推进 `draftRevision`。该值用于候审预览与冻结，不参与独立语种保存的冲突判断。预览之后任一入包数据变化，使用旧 `draftRevision` 提交时返回 `REVISION_CONFLICT`。发布或撤下过程中依赖的实时公开资格另按实施方案第 08 节复核。
- **语言配置。** `en`、`zh` 作为首版界面可用语言和全局发布必需语种。首版 `zh` 的界面和样例使用简体中文。`ja` 可先作为内容维护授权。旧数据中的 `cn` 按来源映射到 `zh`，写入及 API 统一传登记的语言代码。会话用于加载界面和已授权编辑区，实际请求按账号最新权限执行。 [首版语言与翻译规则](全球旅游后台首版实施方案.md#04-人员语言权限与全局界面)

```bash
DATABASE_URL="$FM_WORLD_DEV_DATABASE_URL" npm --prefix back-end run admin:bootstrap -- --env dev
DATABASE_URL="$FM_WORLD_TEST_DATABASE_URL" npm --prefix back-end run db:seed:sample -- --env test --profile qa-v1 --group identity
DATABASE_URL="$FM_WORLD_TEST_DATABASE_URL" npm --prefix back-end run test:integration -- --env test
npm --prefix front-end run test:e2e -- --env test
```

1. 运行脚本传 `APP_ENV`，CLI 的 `--env` 必填，两者存在且值不一致时立即退出。服务、命令和测试使用同一套环境解析，均从进程环境读选中环境的 `DATABASE_URL`。`dev`、`test`、`production` 预建不同的数据库和账号，库名分别为 `fm_world_dev`、`fm_world_test`、`fm_world_production`。程序以实际连接查询的库名校验环境，数据库同时含独立的环境标识。首次迁移只有收到 `--initialize-empty`、实际库名符合且目标为空库时才建立标识。已有结构但无标识、标识不符或集成测试指向非测试环境时退出。常规应用账号只读标识，常规启动只启动服务。环境连接、凭据和文件目录由本地私密配置或部署环境提供。
2. M2 导入先以来源映射生成预览和冲突报告。运营核验后提交正式记录，并对账实体数、映射数、未匹配项和待核语言。模块完成后同步切换前端读取和写入路径，使用真库验证正常入口。
3. 正式部署使用构建产物与线上启动入口。管理后台部署依次记录备份及审计水位、执行迁移、检查健康状态、验收授权生效预览，再切换管理流量。客户端服务阶段复核匿名读取、失效链接和恢复结果后才切换公开流量。已应用迁移持续保留，结构变化走新增迁移。 [实施与恢复门槛](全球旅游后台首版实施方案.md#09-实施顺序与完成门槛)

客户端前端以独立响应式 Web 为首个实现，在 `client-front-end/` 交付，沿用仓库的 React、Vite 和 TypeScript 技术基线。第三段按第 05.2 节开发，用第 08.4 节的公开契约夹具验收。第四段将同一客户端接入公开服务。首批入口按下表执行。

| 页面 | 交互与数据读取 |
| --- | --- |
| `/` | 显示语言自称，由旅客选择界面与内容语言。选择后进入列表。直接进入检索或详情且缺语种时，选择语言后返回该页面。 |

### 08.4 前端先行的契约与夹具

前端在 `src/api/` 维护统一请求边界，传输类型依据接口契约。测试或显式开发预览拦截该边界，按同一接口形状返回可复位的合成样本、修订号、分页与错误码。页面只消费请求结果，聚合业务状态归服务端。管理端夹具模拟权限过滤后的响应，客户端夹具只包含公开字段。生产入口仅调用真实接口。真实服务未接通时显示连接状态，实际写操作以真实回执为准。禁止在正式产物中装入夹具、在请求失败后回退到夹具，或从夹具写入业务数据。

开发交接提交覆盖的正常和失败场景。管理端至少覆盖会话失效、权限收回、未找到、修订冲突、字段校验和发布后状态刷新。客户端至少覆盖中英文、语种未发布、撤下、媒体失效、空结果和请求失败。接入真实服务时复用相同页面、请求类型和用户路径，移交第 07 节的真实服务验收。

## 09 服务端开发标准

### 09.1 工程和服务边界

首版采用 Node.js 24 LTS、TypeScript、Fastify 5、PostgreSQL 17 和 `pg`，通过 npm 锁定依赖。数据库采用编号化的增量 SQL 迁移，M0 交付迁移命令并记录版本及校验值，迁移事务与版本记录一同提交。管理端沿用仓库现有技术栈。数据库集成套件用 `node:test`，浏览器验收用 Playwright。M0 锁定可复现的依赖与运行版本。 [Node.js 发布周期](https://nodejs.org/en/about/previous-releases) · [Fastify 校验与序列化](https://fastify.dev/docs/v5.8.x/Reference/Validation-and-Serialization/) · [PostgreSQL 版本支持](https://www.postgresql.org/support/versioning/) · [现有前端依赖](../front-end/package.json)

| 位置 | 职责 |
| --- | --- |
| `back-end/src/server.ts`、`app.ts`、`config.ts` | 进程启动退出、应用装配、环境和数据库身份校验。测试复用应用装配入口。 |
| `back-end/src/modules/` | 按 `identity`、`geography`、`catalog`、`content`、`publication`、`imports`、`coverage` 分模块交付。HTTP 层解码并输出契约，应用层持有权限和事务边界，仓储层执行 SQL 并接受调用方的事务连接。跨模块调用使用所属模块公开能力或只读 DTO。 |
| `back-end/migrations/`、`back-end/test/` | 增量迁移、夹具、集成和契约测试。所有带状态的验证按第 06 节隔离目标库。 |

每批先定共用请求、响应 JSON Schema 和样例。前端夹具、后端路由校验和传输类型引用同一版本。后端启用路由后据此生成 OpenAPI，并检查真实响应通过共享定义。接口字段、枚举或状态变更先更新权威契约与样例，再同步实现。契约测试覆盖必填字段、省略与空值、错误结构和公开字段白名单。数据库规则以版本化迁移实现。健康检查同时验证访问的数据库身份和目标迁移版本。日志关联 `requestId`、路由、状态和耗时，操作审计记录业务 ID、操作者和状态变化，省略凭据、会话、令牌和未经授权的正文。退出时先停止接收新请求，再收尾在途操作和数据库连接。 [前后端共用契约](全球旅游后台首版接口契约.md#050-前后端共用契约)

### 09.2 账号、范围与事务

1. 登录密码按 Argon2id 哈希保存。会话使用加密安全随机凭据，数据库保存其单向校验值、账号、`expiresAt` 和可空 `revokedAt`。首版会话自签发起最长 12 小时，注销和停用后按最新数据库状态拒绝旧会话。登录按账号标识与来源分别限速，凭据错误、账号不存在及停用使用相同失败响应。Cookie 和 CSRF 规则见第 04 节。 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) · [OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
2. 人员页可用本节角色预设填充动作，另可在可委派范围内选择具体动作。语言相关的 `translations.*` 和 `coverage.review` 要求同一条授权覆盖目标语种和对象范围，且语种在账号支持清单中。可委派范围、动作和语种取授予者授权的同条约束。对象当前、草稿与历史的归属依据统一引用实施方案第 02.1 节。 [归属变更与授权](全球旅游后台首版实施方案.md#021-归属变更与授权)
   系统根为固定作用域，UUID 为 `00000000-0000-4000-8000-000000000001`。授权外键指向与地理身份共用的稳定记录。M1 在正式环境仅可授予系统根范围，测试范围使用与 M2 相同的稳定地理身份和父链结构。M2 接入国家及下级节点，继续沿同一父链计算后代关系。账号归属范围由 `homeScopeId` 确定。修改全局账号属性须覆盖该账号归属与已有授权范围，单次授予或收回按目标授权校验。任何会影响根管理员存续的操作先锁系统根的保护记录，再校验最后一位有根级人员管理权限的活动账号。
3. 授权以当前账号行和存在的实际授权为准，列表、计数、搜索、候选及 DTO 解包时统一过滤。读接口用同一一致性读视图取授权和受限数据。敏感写入按实施方案第 04、08 节锁定授权与业务对象，同一事务中复核作用域和修订号，写状态、相应审计和幂等回执。数据库约束至少覆盖字段映射第 03 节列出的唯一键、关系外键、范围引用和单一待审记录。同一对象的聚合草稿在同一对象锁下推进，逐语种修订规则见第 04 节。
4. 重放前重新鉴权，重复并发操作通过唯一键占位，胜出写入与回执一起提交。预期业务失败返回第 05.3 节的错误。回滚后业务数据、引用索引与成功回执同时撤回。需要留下失败审计时，只记录已知结果，区分权限拒绝、申请冲突与处理异常。测试用真实事务验证先后顺序、服务重启和重试。

### 09.3 文件、导入与公开链路

1. 文件字节存于环境隔离的私有目录，数据库登记服务端生成的 `fileId`、`scopeId`、`purpose`、格式、大小、摘要和状态。导入仅接受 UTF-8 JSON，最大 10 MiB。素材首批接受 PNG、JPEG、WebP，最大 20 MiB，服务端校验文件格式。请求中的文件名仅作显示。业务消费时复核文件是否可供操作、用途和归属。异常上传或应用阶段失败时，未完成的文件保持不可用并清理临时字节。
2. 首批导入文件结构为 `{schemaVersion: 1, records: []}`，单项为 `{entityType, externalId, sourceRevision, fields, translations}`。引用来源系统内的对象时传 `{entityType, externalId}`，预览以第 03 节来源键映射为内部 ID。为冲突返回 `conflictId`、原因和有权限查看的候选，应用请求通过 `resolutions` 提交 `{conflictId, decision, targetId?}`，决定取 `accept-mapping` 或 `defer`。应用锁定批次后以保存的输入摘要、来源映射和预期修订重验，事务提交已核对记录、继续暂存的冲突及计数。导入写草稿，不触发发布。
3. 各端启用后，公开读取、管理预览及导出下载响应使用 `Cache-Control: no-store`，文件目录保持私有。受控导出由本人账号访问，首版最多 100 个目标，保留生成时的版本及语种，链接有效期为一小时。交付前复核权限、确切版本及许可。第 07 节验证历史与当前读取的差异、旧链接及恢复后的限制。

### 09.4 客户端服务与唯一发布源

第四段在 `back-end/src/modules/publication/` 内新增独立公开路由，默认与管理服务同一进程部署。公开站点只转发接口契约第 05.2 节的路由，继续保持管理路由的会话与来源限制。第二段仅装配管理路由，真实生效预览使用同一个发布应用服务和授权媒体入口。

客户端服务调用发布模块的只读能力，读取当前生效版本、允许公开的译文、依赖资格和素材许可。公开处理器统一序列化白名单字段，搜索、详情及媒体以同一公开资格判断为准。业务表、版本和撤销状态仍归管理后台持有。禁止建立另一套内容写入、复制为第二份权威资料，或利用管理会话代理匿名读取。若后续拆成独立进程，应通过发布模块的受控只读接口接入，保持公开契约和验收行为。

联调从管理端通过真实接口操作，客户端连续验证发布出现、切换版本、暂停、恢复和确切版本撤销。分别验证列表与详情的中英文、过期媒体链接、白名单字段和无需管理会话。外部 HTTP 用例从客户端公开来源发起，并断言该来源无法访问管理路由。
