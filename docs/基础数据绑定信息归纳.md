# 基础数据绑定信息归纳

更新时间：2026-07-03

## 核心原则

- 信息中心负责维护可复用、多语言、可被多个对象绑定的标准资料。
- 基础数据负责把国家、省份、城市、点位、地标绑定到信息中心资料，只保存资料 id。
- 每个基础数据对象允许维护一项 `customSupplement` 自定义多语言补充，用于记录当前对象特有、暂时无法沉淀成统一资料的说明。
- 如果同类信息会被多个层级或多个对象复用，应优先上收到信息中心，不在基础数据表单里重复录入。

## 可合并维护的信息

| 信息类型 | 归并建议 | 说明 |
| --- | --- | --- |
| 交通方式 | 合并到信息中心“交通” | 省份、城市只绑定交通方式 id；飞机、铁路、公交、出租、租车等不在各层级重复维护正文。 |
| 支付方式 | 合并到信息中心“支付” | 国家入境信息绑定支付方式 id；货币作为支付模块内嵌基础数据查看。 |
| 语言、货币、时区、气候 | 合并为国家层基础绑定 | 这些信息通常由国家决定，不应在省份、城市、点位、地标重复维护。 |
| 国标、电压、插头、电话 | 合并到信息中心“国标” | 国家层按国标类型绑定，其他层级继承国家配置。 |
| 入境、海关、通讯、网络、交通规则、驾照 | 合并到国家入境信息 | 这些是国家级旅行约束，不下沉到省份或城市。 |
| 文化、习俗、宗教 | 合并到信息中心“文化”作为通用资料；省/市只绑定当前层级旅游资料 | 国家层维护通用文化约束，省/市维护层级特色，不重复录入通用禁忌或宗教规则。 |
| 省份特色维度 | 收敛为区域地貌、文化圈层、遗产集群、风味体系、季节活动 | 省份表达跨城市共享的区域结构，强调片区、走廊、圈层和季节窗口。 |
| 城市特色维度 | 收敛为城市街区、城市生活、餐饮场景、城市遗产、城市活动 | 城市表达游客在城市内的体验场景，强调街区、生活方式、餐饮、活动和城市记忆。 |

## 需要保留层级差异的信息

| 层级 | 保留信息 | 原因 |
| --- | --- | --- |
| 国家 | 入境、国标、语言、货币、安全、文化等国家级约束 | 游客跨国旅行前必须确认，且会影响所有下级对象。 |
| 省份 | 区域地貌、文化圈层、遗产集群、风味体系、季节活动、建议停留天数 | 表达跨城市共享的区域性体验，不维护城市街区、城市活动等城市粒度细节。 |
| 城市 | 城市街区、城市生活、餐饮场景、城市遗产、城市活动、建议游玩天数 | 表达城市内可被游客感知的体验场景，不维护省域文化圈层或跨城季节窗口。 |
| 点位 | 开放、票务、预约、设施、到达、无障碍、拥挤提示、建议游玩分钟 | 面向游客到访具体位置时的执行信息。 |
| 地标 | 讲解、参观动线、拍摄、排队、最佳时段、文化解读、建议游玩分钟 | 面向地标内部参观体验，不反向维护城市或点位通用信息。 |

## 可进一步抽象的相似项

- 点位“拥挤提示”和地标“排队提示”可在信息中心归并为“人流/排队”资料类型，基础数据层仍保留各自字段以表达使用场景。
- 点位“开放提示”、地标“最佳时段”可归入“到访时间”资料族，但点位关注是否开放，地标关注体验时段。
- 点位“到达方式”和地标“参观动线”都属于路径信息，但前者是到达点位，后者是地标内部参观，不建议直接合成一个字段。
- 省份和城市不再共用同一套特色类型：省份强调跨城市区域结构，城市强调城市场景体验。两者都通过旅游资料模块维护，但 `level + typeValue` 不相同。

## 当前实现

- 国家绑定信息保存在 `src/store/useCountryInfoBindingStore.ts`，新增 `customSupplement`。
- 省份、城市、点位、地标绑定信息保存在 `src/store/useTourismInfoBindingStore.ts`，各层级新增 `customSupplement`。
- 省份、城市、点位、地标共用 `src/components/TourismInfoBindingModal` 渲染自定义补充。
- 国家管理页在信息绑定弹窗底部渲染同名自定义补充。
